Boba Job Find

Steep your search. Sip the good offers.

A free, open-source, local-first desktop app (Windows / macOS / Linux) that finds job offers every day, tells you which are worth your time and why, writes truthful tailored applications, and sends them only as far as you allow. It productizes the MadsLorentzen/ai-job-search methodology.

Runs on your machine · no account · no Boba server · no Boba bill · 2026-10-04 · Summary of docs/ — source docs are the source of truth
01

Vision & positioning

docs/product/product-brief.md · docs/research/competitors.md

Job seekers applying across borders lose hours a week to the same loop: scrolling boards, guessing which posts are real and winnable, rewriting a CV from scratch, losing track of replies. The tools that automate this are cloud SaaS with weekly billing and generic output.

What Boba keeps from the upstream methodology

Hard eligibility gates

Work eligibility, language, location, salary floor — checked before scoring, with quoted evidence.

Transparent fit scoring

Two axes and a weighted Rank, every factor explainable.

No-fabrication rule

Claims come only from the Profile; gaps are declared, never stuffed.

Verified documents

ATS-safe PDF/DOCX, mechanically checked for text layer and page budget.

What Boba adds

  • First-run wizard (≤ 15 min install → first ranked list).
  • Daily search from the system tray with native digest notifications.
  • Ranked inbox showing two scores — Fit and Quality — with evidence.
  • Per-application tailoring studio (ATS PDF + DOCX, ES/EN).
  • Self-updating tracker fed by locally-read recruiter replies.

Competitive field

11 incumbents teardown (Teal, Huntr, Simplify, Jobscan, LazyApply, Sonara, AIApply, Careerflow, Kickresume, Rezi, Jobright). Two clusters: (A) tailoring/ATS with high doc quality and no auto-submit, and (B) volume/auto-apply. Every one is cloud SaaS; none is local/offline; none keeps your data on your machine; autopilot output reads identically and gets rejected at scale.

Where a local-first desktop app wins

Data residency by default · BYO model · consent-gated pipeline · native cross-OS incl. Linux/offline · no billing traps · explainable scoring · truthfulness guardrails.

What we won't beat them on

Breadth of ATS autofill coverage, aggregator-scale freshness, turnkey zero-setup UX. Winning move: own the private, judgement-heavy layer; interoperate with free autofill extensions.

Core experience

docs/product/PRD.md · docs/design/EXPERIENCE.md · docs/research/offer-scoring.md

Onboarding wizard — 10 steps

  1. Language & theme — EN/ES; theme follows OS.
  2. Agent CLI — detect installed CLIs with version/path/health; pick one + model; test call. None works → Limited mode.
  3. Profile import — Master CV (PDF/DOCX/LinkedIn export); every field reviewed with its source excerpt; nothing saved until confirmed.
  4. Profile gaps — work eligibility, CEFR level, notice period; skippable (lowers Confidence).
  5. Preferences — roles, seniority, Salary Floor, locations/timezones, work mode, languages, deal-breakers, excluded companies.
  6. Sources — recommended Safe Sources pre-selected; Risk Tier shown; add custom RSS/URL/ATS board.
  7. Email (optional) — Gmail send-only default; Outlook/Graph and IMAP/SMTP read+send. Explains exactly what Boba reads vs sends.
  8. Apply Mode & schedule — default Review (Auto cannot be enabled here); daily run time (default 08:00); launch-at-login off.
  9. Recovery backup — mandatory on unsigned builds: save the one-time recovery key + backup file.
  10. First run — start a Search Run and open the Inbox with live progress.

The daily loop

1 · Steep (background)

Tray scheduler runs the daily search → fetch sources (rate-limited) → normalize → deduplicate/cluster → hard gates → deterministic scoring → digest notification.

2 · Sip (triage)

Today + Inbox show a ranked list. Each offer explains the score: what matched, what is missing, what looks off (stale post, no salary, layoffs). One obvious next step.

3 · Tailor

Studio produces a tailored CV + cover letter in the offer's language, using only Profile facts. Changed lines highlighted; claim traceability; ATS checks.

4 · Apply & track

Review mode (approve each send) or opt-in Auto. Tracker kanban updates itself from locally-read recruiter replies, proposed as status changes.

Offer ranking — Fit + Quality

Deterministic, offline, versioned. Rank = 0.65·Fit + 0.35·Quality (weights user-adjustable). A role you'd easily get at a bad company must not outrank a stretch at a great one — hence two axes, always shown.

Rank — verdict

● Strong · 75

Verdict bands: Strong ≥75 · Good 60–74 · Moderate 45–59 · Weak 30–44 · Poor <30

Hard gates first

Work eligibility, language, location/work mode, comp floor, deadline, right-to-work. Each returns PASS / FLAG / VETO with the exact quoted evidence. A VETO is never a silent drop — shown in “Excluded” with an override.

Confidence, not just score

Every factor carries {score, weight, matched[], missing[], evidence[], confidence}. Missing data renormalizes weights and lowers Confidence — never imputed to neutral. A high score at low Confidence is a Lead, not a verdict.

Anti-ghost signals (Q4)

Posting age > 90 days (27.6% of openings), repost within 30 days, stale by ATS, layoffs/freezes, vague description, no salary. Deprioritized, not deleted. Scam patterns get a hard-red badge.

The LLM may extract features and narrate the score, but never sets or changes a number (AD-5, AD-8). Weights are calibrated from the user's real outcomes, and never changed silently.

Kanban stages (binding vocabulary, not renameable): Saved → Preparing → Applied → Interviewing → Offer · Hired · Rejected · No Response · Withdrawn. Terminal stages collapse. The app never talks to an LLM API directly and never sees the user's LLM credentials — the CLI owns them. The agent's only tools come from boba-mcp. The LLM proposes; the core disposes.

Hexagonal: domain ← app (use cases & ports) ← adapters. src-tauri/src is the composition root.

boba-app

Architecture decisions (ADR list)

ADR-001Desktop shell: Tauri v2. Rust core holds logic/IO; React in the system webview; minimal capabilities; CSP default-src 'self'.
ADR-002AI engine via user-installed agent CLIs + boba MCP. One CliDriver per CLI; the agent only uses boba-mcp tools; the LLM proposes, the core disposes.
ADR-003Upstream reuse: re-implement the methodology, don't vendor. Port gates/rubric/verification to Rust; keep upstream-compatible export formats; keep the MIT notice.
ADR-004Storage: SQLCipher-encrypted SQLite + OS keychain. 32 random bytes in the keychain; Argon2id passphrase fallback; blobs inside the DB; forward-only migrations.
ADR-005Source access classes, scraping and auto-apply policy. Manifest declares access class, legal tier, apply capability. Default-on public JSON/RSS; opt-in scrape/session. No evasion, ever.
ADR-006Document rendering: Typst (PDF) + docx-rs (DOCX) from one model. One CvDocument JSON; layout + ATS text-layer + fabrication checks before any send.
ADR-007No Python sidecar; boba-mcp is the only sidecar. Upstream tools ported to Rust/ONNX; Python only for dev-time scripts.
ADR-008UI stack: React 19 + Tailwind v4 + shadcn/ui + TanStack Query + tauri-specta. Self-hosted @fontsource fonts; i18next + ICU catalogs shared with the core.
ADR-009DB key custody across unsigned builds, and the Locked state. One persistent self-signed macOS cert; never mint a key over existing data; passphrase unlock per login; forced recovery backup. (See §07.)
ADR-010Untrusted-content tasks require verified tool lockdown; agent output is untrusted. Hard gate, no user override; agent text rendered plain/sanitized and re-enveloped. (See §07.)
07

Security & privacy highlights

docs/architecture/architecture.md §13 · ADR-009 · ADR-010 · docs/reviews/planning-audit.md

Threat model (STRIDE highlights)

  • Prompt injection → unwanted action: no action tools, MCP only, untrusted envelopes, policy gate before any outbound step.
  • Exfiltration via the agent: untrusted-input tasks run only on CLIs with verified tool_lockdown; otherwise unavailable.
  • Stored injection / XSS: untrusted_origin, sanitized render, Typst receives strings as data.
  • OAuth code interception: loopback only, PKCE S256, single-use 256-bit state.
  • Local DB theft: SQLCipher, key in keychain, blobs in DB, secure_delete.
  • Supply chain / update hijack: lockfiles, cargo-deny, pinned Actions SHAs, signed updater (minisign).

Privacy posture

  • No telemetry, no analytics, no remote crash reports.
  • Logs stay local and are redacted; secrets never logged.
  • Every network destination listed in Settings → Privacy.
  • No backend — the vendor never becomes a data processor.
  • The LLM provider does see task inputs (including recruiter-email text for classify_emails), disclosed at onboarding, with a deterministic-only option.

Audit rulings (approved by Diego, 2026-10-05)

ADR-009 — key custody, signing & Locked state

Every macOS build signed with one persistent self-signed certificate (pinned DR; CI blocks ad-hoc) so Keychain survives updates. Never mint a key over existing data — if the key can't be read, enter the Locked state. Passphrase path: unlock once per login, zeroized memory, idle timeout (default 8h). Scheduled jobs while locked record skipped_locked + one notification — never a silent success. Forced recovery backup before first run on unsigned builds.

ADR-010 — untrusted content requires tool lockdown

Untrusted-input tasks (extract_postings, narrate_scores, tailor_application, review_application, classify_emails) require a CLI proven to have no native web/fetch, no networked shell, no writes outside the workspace. Otherwise the task is unsupported — hard gate, no override. Agent output is itself untrusted: plain/sanitized render, Typst as data only.

OAuth — loopback + PKCE

RFC 8252 loopback only + PKCE S256 + single-use 256-bit state, one-shot listener. The deep-link fallback is removed (eliminates scheme-squatting). Bundled public desktop clients plus a BYO client-ID fallback; no client secret treated as confidential.

Gmail — send-only in MVP

The bundled Google client requests gmail.send only. Reading recruiter replies uses a BYO Google client (gmail.readonly), IMAP, or .eml import; MS Graph covers Outlook read+send. Restricted scope on the project client and CASA are deferred.

Enforcing the guarantees

Hash-chained audit log (AD-12)

Every outbound action writes intent before and outcome after, with blake3 over RFC 8785 canonical JSON. UPDATE/DELETE rejected by triggers; latest hash anchored in the keychain; crash intents resolved at startup.

Apply policy engine (AD-11)

Single core function decide(). UI never decides. Kill switch re-checked immediately before every irreversible step; caps/pacing/holds are scheduler-owned so closing the UI can't bypass them.

Fabrication guardrail (AD-15)

Every claim-bearing item carries fact_ids[]. Validator rejects items with no/unknown facts; missing keywords go to declared_gaps[] — never added to the text.

  1. Auto-apply reality. Sanctioned candidate auto-apply exists only via InfoJobs; ATS apply APIs need an employer key; LinkedIn/Indeed/WWR prohibit automated submission. Resolved: session-board auto ships in MVP behind per-source opt-in, executed by the core, risk user-accepted.
  2. Reading Gmail. Restricted scope normally needs CASA. Resolved: bundled send-only client + BYO read client, Graph, IMAP or .eml; CASA deferred.
  3. Agent CLI variance. Different headless flags/formats/limits. Mitigated by the CliDriver contract, runtime capability probes, pinned fixtures and a supported-CLI matrix (see prd-addendum A.1).
  4. Token/quota cost of the daily run. Mitigation: deterministic pre-filter, LLM only on top candidates, per-run budget.
  5. Install friction. The user still needs an agent CLI installed; Boba detects missing ones and links guides, does not bundle them. Limited mode covers searching/tracking without AI.
  6. Legal. Browser-automation sources stay opt-in with a stated warning and no default-on.

## Findings

### 1. HIGH — `Money` fallback invents salaries from any number (CONFIRMED)
- File: `src-tauri/crates/boba-app/src/ingest/normalize/mod.rs` (`normalize`, `money = ... .or_else(|| Money::parse(&description_text))`), and `boba-domain/src/posting/mod.rs` `Money::parse` / `first_amount_minor`.
- Failure: a description with no salary but a number early on, e.g. `"Founded in 2015, 40 engineers."`, yields `Money { amount_minor: 201500, currency: "USD", period: Year }`. The currency and period default when the text has no marker. This breaks the module's own rule "Nothing is invented — a missing field stays empty" and feeds false pay into S3.7 salary floors (hard deal-breakers) and the S6 fit scoring.
- Expected: `money` is `None` unless a salary field is present, or the description has an explicit salary marker (currency symbol or code, and a period word or range).
- Fix: drop the description fallback, or require an explicit currency and period marker in the description before reading an amount. Add a negative test with a non-salary number in the description.

### 2. MEDIUM — i64 overflow on untrusted salary text (CONFIRMED by reading)
- File: `boba-domain/src/posting/mod.rs`, `first_amount_minor`: `return Some(value * 100);`.
- Failure: a first number of 18 or more digits (for example `salary_text: "123456789012345678"`, or a long numeric ID in the description) parses as i64 and then overflows on `* 100`. Debug builds panic; release builds wrap to a wrong value. This input is untrusted (AD-7).
- Expected: no panic, and no wrapped value.
- Fix: `value.checked_mul(100)` (and the `* 1000` shorthand) and return `None` on overflow. Add a test with an 18-digit value.

### 3. LOW — provenance rewrite contradicts the migration comment and AD-19 intent
- File: `boba-store/src/repos/postings.rs`, `insert_provenance`: `ON CONFLICT ... DO UPDATE SET url, raw, fetched_at`.
- The migration header and `ingestion.rs` say provenance is "appended, never rewritten" (AD-19). The upsert rewrites `raw` on re-observation.
- Fix: either `ON CONFLICT DO NOTHING` (keep the first observed payload), or change the comments to say a re-observation refreshes `fetched_at`/`raw`, and state that in the doc. Pick one and make the code and comments agree.

### 4. NIT
- `0008_postings.sql` header: "erD: architecture.md §12" should read "ERD".
- `posted_at` is stored as given. AD-17 requires UTC RFC 3339. Validate or document that the source is trusted to send RFC 3339.

## Blocking

### B1. Re-unlock after an idle expiry panics (duplicate port mount)

- **Where:** `src-tauri/src/wiring/mod.rs` `gate()` (sets `StoreStatus::Locked`) and `mount_with_key()` (only short-circuits on `Ready`); `mount_port` asserts on a duplicate `manage`.
- **Repro (verified):** a temporary test, since reverted, did this: mount ports and set `Ready`; hold a `KeySession` with a zero idle window; call `port()`, which goes through `gate()`; the state becomes `Locked`; then `mount_ports` runs again, the same call `adopt()` makes. It panics with `duplicate port line in port_list`, so `#[should_panic(expected = "duplicate port line")]` passes.
- **Expected:** after an idle expiry, the user re-enters the passphrase, the key session is re-armed, and the app keeps working with no panic.
- **Actual:** the ports stay mounted, the gate sets `Locked`, and the unlock path calls `Store::open_with_key` then `adopt` → `mount_ports` → panic.
- **Why it was missed:** `mounting_a_key_over_an_open_store_is_a_no_op` covers only the `Ready` state, and no test covers idle → re-unlock.
- **Fix (for dev-4):** make the "already mounted" check depend on whether ports are mounted, not on the status enum. For example, keep a `mounted: bool` in `StoreState`, or in `mount_with_key` skip the open and mount when the ports are present, and re-arm the session only. Add a test that runs the full idle → `port()` → `mount_with_key` (or its inner flow) → `port()` cycle and expects success.

## Verified OK

- **Argon2id parameters:** m=19 MiB, t=2, p=1, Argon2 v0x13, 32-byte output. These are the OWASP-recommended minimums. Params are read from the record, and the record is checked for version, kdf name, output length and salt shape.
- **Salt file:** `boba.db.kdf` holds salt and parameters only. `the_kdf_record_never_holds_the_key` covers it. Written with 0600 (`the_kdf_record_is_owner_only`).
- **Key never on disk:** derived in memory only. Passphrase and key buffers are `Zeroizing`. `to_hex` returns `Zeroizing`.
- **Never mints over existing data:** a database with no record returns `NoPassphrase` (`an_existing_database_without_a_record_refuses_the_passphrase`).
- **Wrong passphrase:** `verify_key` proves the key before mount or unlock; the store and session stay closed.
- **No secret logging:** the only logs are `reason` and `message_key` (`commands/unlock.rs:151,159`). The passphrase and key are never logged.
- **Locking:** `store_state` / `set_store_state` hold the `StoreState` mutex only for read or write, with no `.await` and no nested locks. `gate()` releases the session lock before taking the store-state lock. Poisoned locks are recovered. No deadlock.
- **IPC:** three lines in `command_list.rs`. The one-line `ERROR_FRAGMENTS` addition in `boba-app/src/i18n/mod.rs` is accepted (standing rule).
- **Bindings:** generated, and `gen-bindings --check` passes.
- **ADR-013:** present and indexed in `adr/README.md`.

## Residuals for Diego (security gate, not blocking for merge once B1 is fixed)

1. **The key stays in memory after idle.** The open `Store` (`db/mod.rs:77`, `key: DbKey`) and its r2d2 pool keep the key hex for the process lifetime. Idle expiry zeroizes only the session copy. ADR-013 documents this for the pool and writer, but the "dropped on idle timeout" wording in ADR-013, the `KeySession` docs and the bindings doc is overstated. Recommended: reword those to "the session copy is dropped; the open store keeps its key until quit", or accept as-is.
2. **The idle gate covers ports only.** Already-open `SQLite` connections and any `Arc<P>` a caller already holds keep working after idle. ADR-013 accepts this (in-process attacker is out of scope). Long-running work (scheduler, agent runs) that caches a port `Arc` would bypass the gate. Flag for S5.1.
3. **KDF params are read from the record and not bounded.** A local attacker who can write the app-data dir could set a huge `m_cost` and cause a memory-exhaustion DoS on unlock. It cannot weaken the existing store, because a changed parameter derives a different key that fails verification. Recommended: clamp to a sane range or reject values above the OWASP-recommended ceiling.
4. **Brief window on record creation.** `write_record` uses `fs::write` and then `set_permissions(0600)`, so the file exists at the default umask (0644) for an instant. It contains only salt and parameters, so the impact is low. Recommended: `OpenOptions::new().create_new(true).mode(0o600)`.
5. **Non-zeroized key string in `verify_key`.** `format!("PRAGMA key = ...")` builds a plain `String` with the key hex. The same pattern already exists in `db::apply_key` (pre-existing, not introduced here). Low risk, but the new code repeats it.
6. **Passphrase outside zeroized memory on the JS side.** The passphrase is a React `useState` string and also crosses IPC as JSON. The Rust side wraps it in `Zeroizing` immediately, but the webview copy is not cleared. Accepted for a local desktop app; flag only.
7. **Windows record permissions.** `owner_only` is a no-op on Windows (accepted in S1.2a: app-data is user-scoped).
8. **Manual AC3/AC4 pending.** `docs/qa/macos-upgrade-test.md` is the manual plan; it has not been run.

## Round 2 (3c6b91a) — APPROVED

- **B1 fixed.** `mount_with_key` decides "already open" from the mounted ports, not the status enum. `mounted` is set only by `adopt()`. Re-unlock after idle re-arms the session and sets the state to `Ready`, without a second `Store::open_with_key` or `mount_ports`. Regression test `an_idle_gated_store_unlocks_again_without_mounting_ports_twice`. I reproduced the panic in round 1 with a temporary test, then reverted it.
- **Stale-Retry guard (3c6b91a).** `wiring::mount()` returns early when the ports are mounted, so a late Retry on an open store can't open a second store and mount ports again. Test `retrying_the_keychain_on_an_open_store_is_a_no_op`.
- **Residual 3 closed.** KDF params from `boba.db.kdf` are bounded (m 8..=1 GiB in KiB, t 1..=16, p 1..=8) and refused, never clamped. Test `a_tampered_kdf_record_is_refused_before_any_derivation`.
- **Residual 4 closed.** The record is created with `create_new` and mode 0600 at open (no chmod window), then `sync_all`. Test `an_existing_record_is_never_replaced`.
- **Residual 5 closed.** The `PRAGMA key` string in `verify_key` is `Zeroizing`.
- **Residuals 1 and 2 accepted** (orquestador standing OK): the open store keeps its key until quit, and the idle gate covers ports only. ADR-013 and the `KeySession` docs now say so, and flag that a caller holding an `Arc<P>` bypasses the gate for S5.1.

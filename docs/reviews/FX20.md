## Root cause

`src-tauri/tauri.conf.json` declares `externalBin: ["binaries/boba-mcp"]`. On
each build, `tauri-build` (2.7.1, `src/lib.rs` around lines 736–740) copies
`src-tauri/binaries/boba-mcp-<triple>` into `target/<profile>/boba-mcp`. Those
placeholders are tracked in git as 0-byte, non-executable files until a release
build fills them. The `boba-mcp` bin target writes the same path, so the two
race. When the copy wins, the shim tests spawn an empty file and fail with
`spawn the shim: PermissionDenied`. `docs/reviews/S7.3.md` records the same
0-byte `target/debug/boba-mcp` outcome.

The fix removes the collision at its source: the bin target becomes
`boba-mcp-shim`, and the shipped sidecar keeps the name `boba-mcp`.

- No other reference to the old bin path, except `AGENTS.md` line 60 (see notes).

## Notes (non-blocking)

1. **Not reproduced end to end.** My runs did not show `tauri-build` overwriting
   `target/debug/boba-mcp` during a build; the copy was skipped on cached builds.
   The root cause is supported by the `tauri-build` source, the tracked
   placeholders and S7.3, not by a live reproduction.
2. **The new regression test is a guard, not a reproducer.** It asserts the
   spawned binary is non-empty and executable. It cannot fail through the old
   race, because that race can no longer touch `boba-mcp-shim`. It protects
   against a future rename that reintroduces the collision.
3. **CI evidence is absent.** Release run `39111385539` failed in
   `Verify and publish` (`release v1.0.0-beta.2 is still a draft; publish it`),
   after all build jobs passed. No shim test runs in that run, so it neither
   confirms nor refutes FX20. The orquestador should not cite it as the flake's
   evidence.
4. **`AGENTS.md` line 60** says to delete `target/debug/boba-mcp` when tests fail
   with `Permission denied`. That workaround is no longer needed after this
   change. The orquestador owns `AGENTS.md`, so the line is theirs to update.

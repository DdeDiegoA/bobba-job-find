## Findings

### F1 (blocking, needs orquestador decision) — the golden ScoreCard does not reach Rank 75.2

- **Evidence.** `src-tauri/crates/boba-domain/tests/golden/main.rs`:
  - `the_published_worked_example_ranks_75_2` checks `rank_from_axes(81.3, 63.9)` = 75.2. It is a formula check on hard-coded published axes, not a ScoreCard.
  - `the_worked_example_scores_end_to_end` — the real golden card for §9's inputs — asserts Rank **67.14**, Verdict Good, Fit 67.44, Quality 66.56.
- **Root cause (verified by hand).** `docs/research/offer-scoring.md` §9 is internally inconsistent. Its factor column, weighted by its own §6 weights, gives Fit 82.1 and Quality 73.05. The published axes 81.3 and 63.9 do not follow from it. Only the published axes give 75.2. Dev-1's report matches this arithmetic.
- **Why it matters.** AC4 literally says the *golden ScoreCards* include the §9 example at Rank 75.2 ±0.1. No ScoreCard produced by this model reaches 75.2 for §9's inputs. The end-to-end card lands at 67.14.
- **Expected vs actual.** Expected: a golden ScoreCard with Rank 75.2 ±0.1. Actual: the formula reproduces 75.2 only from hard-coded axes; the scored card is 67.14.
- **Options for the orquestador (recommended first):**
  1. **(Recommended)** Keep the code as is. Re-word AC4 in `stories.yaml` / `slices.yaml` to pin the end-to-end golden card at 67.14 and the published-axes formula at 75.2, and add a note under §9 of `offer-scoring.md` that its factor column does not average to its axes. This is a docs/AC change, no code change.
  2. Tune the factor model so the end-to-end card reaches 75.2. Not recommended: it fits the code to a document whose own numbers disagree.
- No code change requested from dev-1 until the orquestador picks an option.

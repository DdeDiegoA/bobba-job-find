## No check got weaker

Compared `scripts/release/verify-release.mjs` on main with the new `lib/verify-release.mjs`:

- **Asset list and `latest.json`:** `checkAssets` and `checkLatestJson` still run in both modes, with the same inputs.

- **Workflow order:** `Download` → `fix-latest-json` → `Installers and latest.json (draft)` → DMG identity → `Publish` → `Verify the published release` (re-downloads the attached `latest.json`, `--published`). `workflow-order.test.mjs` locks this order and the mode flags.

## Findings (non-blocking)

1. **Residual risk: the HTTP probe runs after publication.** Before, a broken platform URL blocked the release from going public. Now the draft pass checks the URL form and asset names before publish, but a 404 on a download URL is only caught after publish. A failed published pass leaves a public release with a broken `latest.json`, so installed apps fail to update until someone acts. Suggested follow-up: on failure of the published pass, revert the release to draft, or document the manual recovery in `docs/install/RELEASING.md`. Not a blocker for beta.3 if the owner accepts it.
2. **Draft pass does not check that the release is still a draft.** Harmless: the pass only runs before `gh release edit`. Noted only so the owner knows the guarantee moved, not lost.

## Acceptance checks

- **Files and shapes (AC1):** profile JSON + Markdown, `job_search_tracker.csv` with the upstream 14-column header verbatim, `applications.json` with every status, `seen_jobs.json` as the `{seen: …}` map, `applications/<company>_<role>/` with PDF and DOCX, and `audit.csv`. Each has a test.
- **Tracker `saved` rows:** left out of `job_search_tracker.csv`, kept in `applications.json` (test `writes_the_tracker_csv_with_the_upstream_header_and_leaves_saved_rows_out`).
- **Status vocabulary:** `AppStatus` spellings match the upstream vocabulary exactly (`drafted, applied, interview, offer, hired, rejected, no_response, offer_declined, withdrawn`, plus our local `saved`, which the tracker excludes).
- **Unencrypted warning (AC1):** the Settings → Privacy → Export button stays disabled until the warning checkbox is acknowledged. The export runs on a blocking thread through `ExportPort`; the command carries only the folder path.

## Secrets check (orquestador ask)

- **Tables read:** the export reads only `profile` and `profile_fact`, `application` and `status_event`, `posting`, `posting_source` and `source`, `document`, `scoring` cards, and `audit_event`. It never reads `email_account`, `setting`, keychain references, cookies or session data.
- **Credentials at rest:** tokens live in the OS keychain (`0009_email_accounts.sql`), so the DB holds only a `secret_ref`. The export never reads that column.
- **URLs (finding 2, fixed):** `public_url` strips the fragment, query and embedded userinfo from `applications.json` `apply_url` and `seen_jobs.json` `url`. Test `strips_tokens_from_exported_urls` seeds `?token=`, `?session=` and `user:pw@` and asserts they are absent.
- **Standing proof (finding 3, fixed):** test `never_writes_credential_bearing_tables` seeds an `email_account` row and a token `setting`, then asserts no exported file contains the address, the token value or the `keychain://` reference.

## Upstream format (orquestador ask)

- **`seen_jobs.json` entry schema (finding 1, fixed):** every entry now carries `key`. Test `writes_seen_jobs_in_the_upstream_seen_map` pins the exact key set against the ranked-entry schema from `docs/research/upstream-analysis.md` (`tests/test_rank_state.py`).
- **Residual:** the upstream fixture itself is not in the repo, so the key set is checked against the research doc, not a live upstream file. Accepted for MVP; a fixture import can come later.

## Findings

### F-1 (medium, fixed at `9fda28a`): `seen_jobs.json` entries omitted `key`

- **Where:** `src-tauri/crates/boba-store/src/export/mod.rs`, `write_seen_jobs`.
- **Fix:** `entry.insert("key", key)`, pinned by test.

### F-2 (medium, fixed at `9fda28a`): apply URLs shipped their query string

- **Where:** `write_applications` (`apply_url`) and `write_seen_jobs` (`url`). `canonical_url` keeps non-tracker query params, so signed or session tokens could leave the app.
- **Fix:** `public_url` (host + path only), pinned by test.

### F-3 (low, fixed at `9fda28a`): no test that secrets stay out

- **Fix:** `never_writes_credential_bearing_tables`.

## Accepted residuals

- A token embedded in a URL **path** segment is not stripped. Path-embedded tokens are rare on the boards we support; accepted.
- `audit.csv` keeps `prev_hash` and `hash`. These are chain evidence, not keys, and are needed so a user can verify the chain outside the app.
- Profile facts and notes ship as the user wrote them. That is the user's own data, and the warning covers it.

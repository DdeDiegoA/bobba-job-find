## Security checks (AC2 and token handling)

- Loopback: binds `127.0.0.1` on an ephemeral port, never `0.0.0.0`, never a fixed port. Stray requests get 404 and do not consume the callback. Pass.
- PKCE: verifier is 32 random bytes from `getrandom`; challenge is S256. Pass.
- State: 256-bit random from `getrandom`, single-use (`consumed` is set before any check), 10-minute TTL, checked against the redirect. Pass.
- Deep-link fallback: absent. Pass.
- Tokens: stored only as one keychain entry, referenced by opaque `mail:<id>` under the single `SecretStore` wrapper (`keys::secret_*`, no second keyring wrapper). The `email_accounts` migration has no token column, and the repo test asserts it. Pass.
- Logging: no token, code, verifier or state reaches `tracing` or the UI. Error payloads are OAuth error codes only; the callback `error` value is mapped to a fixed message key. Pass.
- Scopes (AC1/AC3): send-only requests `Mail.Send`; read+send requests `Mail.Read` and `Mail.Send`. `covers()` refuses a mode the grant cannot satisfy. Pass.

## Findings

### F1 (blocking, correctness/security, AC4): disconnect can orphan tokens

- File: `src-tauri/src/commands/email.rs:330-335` (`email_disconnect`)
- Failure: `secrets.delete(...)` fails (for example, the keychain is locked or the platform store errors). The code logs `tracing::warn` and then calls `accounts.delete_account(&id)`. The row, and the only reference to the keychain entry, is gone. The refresh and access tokens stay in the OS keychain with no way for the app to reach them again.
- Expected: AC4 "tokens are revoked where possible and deleted". The comment above it says the leftover entry is "reported, never hidden". Today it is only logged.
- Fix: if `secrets.delete` returns an error, return `Err(EmailFailure::Keychain)` before `delete_account`. The connection row and reference stay, so the user can retry Disconnect. An absent entry (`Ok(false)`) is still success. Add a test with a failing `SecretPort` that asserts the account row survives and the error is `errors.email.keychain`.

## Residuals for Diego (non-blocking, decision needed)

1. **`offline_access` is requested in addition to the mode scopes.** AC1 says "only `Mail.Read` and `Mail.Send` (delegated) are requested." The code adds `offline_access` so Graph issues a refresh token for the background daily run (AD-13). It is shown in plain language in the UI. Recommended: accept; this is a deliberate deviation from the literal AC. Needs Diego's OK.
2. **No bundled public client ID exists yet.** `BOBA_GRAPH_CLIENT_ID` is unset, so the bundled path returns `errors.email.no_bundled_client`. The BYO client-ID path works. AC1's bundled case cannot be exercised until the client is registered (product task, not S8.1).
3. **`Debug` on `TokenSet` and `TokenResponse` prints plaintext tokens.** They derive `Debug`. Nothing logs them today, so this is latent. Recommended follow-up: a manual redacting `Debug`, or drop the derive.
4. **`state` comparison uses `!=`, not constant-time.** The state is a local, single-use, 256-bit value on loopback, so the risk is negligible.
5. **Stray loopback connections are served one at a time with a 5 s read timeout.** A local process can delay the callback by up to 5 s per connection. Local-only, bounded by the 10-minute TTL.
6. **AC4 "purge stored mail" is deferred to S8.3** (no mail table exists yet). Expected by the story split.

## Decision

Approve after F1 is fixed and the test is added. Residuals 1 and 2 need Diego's decision before merge.

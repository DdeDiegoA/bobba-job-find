## Blockers and findings

### H-1 (high): an audit failure stops the engage before the flag flips

- **Where:** `src-tauri/crates/boba-app/src/apply/kill_switch/mod.rs`, `KillSwitchService::set`, the call `self.system.audit_append_intent(...)?` runs **before** `self.engaged.store(engaged, ...)`.
- **Failure scenario:** the audit append fails (chain anchor problem, disk full, locked row). `set(true)` returns `Err` at the `?`. The flag stays off, nothing is parked, no run is cancelled, and the browser stays open. The user pressed Cmd+Shift+K and automation keeps running. That breaks AC1 ("within 2 s all automatic sending stops") and the module's own rule that stopping is the safe direction.
- **Expected:** engaging always stops automation, even when the audit write fails. The audit is recorded best-effort on that path.
- **Fix:** engage first. Flip the flag, persist it, park, cancel and close, and record the audit intent and outcome around that. If the intent write fails, log it and continue. The audit must never gate an engage. Keep the current order for releasing the switch, which can stay audit-gated. Add a test with a system repo whose `audit_append_intent` returns `Err`: assert `engaged()` is true, the live Outbox items are in `NeedsReview`, and the tracked runs are cancelled.

### B-2 (blocker, gate red): `shortcuts::install` panics in the mock app

- **Where:** `src-tauri/src/lifecycle/mod.rs` now calls `crate::shortcuts::install(app)`, which calls `app.global_shortcut()`. The mock app in the test does not register `tauri_plugin_global_shortcut`, so tauri panics: `state() called before manage() for tauri_plugin_global_shortcut::GlobalShortcut`.
- **Why it is only a test failure:** production registers the plugin in `src-tauri/src/lib.rs:34` before `setup`, so the app is unaffected. On `main` this test passes only because `lifecycle::install` did not yet call the shortcut install.
- **Fix (pick one):**
  1. Preferred: the lifecycle test builds its mock app with the plugin, e.g. `tauri::test::mock_builder().plugin(tauri_plugin_global_shortcut::Builder::new().build()).build(mock_context(noop_assets()))`, so the test matches production.
  2. Or guard in `shortcuts::install` with `app.try_state::<GlobalShortcut<R>>()` and log and return when the plugin is absent. Only if option 1 cannot be made to work.
- **Re-run:** the full `cargo test --workspace --locked`, since the run stopped at the first failing binary.

### L-3 (low, optional): unmounted kill-switch port reads as "not engaged"

- **Where:** `src-tauri/src/commands/apply.rs`, `ats_service` (`wiring::port::<dyn KillSwitchPort>(app).ok()`) and `outbox_service`.
- **Note:** the port is mounted unconditionally in `mount_ports`, so this is unreachable in practice. For a safety control, fail closed is the better default: `ats_service` could return an error when the port is missing. Not blocking.

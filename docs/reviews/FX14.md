## Findings

### F1 — HIGH: finish-step run errors are invisible (no `<Toaster>` on that path)

- `src/features/onboarding/steps/finish/index.tsx:30-37`: `toast.error(...)` on a failed first run.
- `<Toaster>` is mounted only in `src/features/inbox/index.tsx:47` and `src/features/tracker/index.tsx:94`. Nothing under `src/app/` or the onboarding route mounts one.
- The wizard hands over to Today after finish, and Today has no `<Toaster>` either. The toast has no host, so the user sees nothing.
- The unit test passes only because it mocks `sonner` (`vi.mock("sonner", ...)`), so the test never checks that a toast can be seen.

**Failure scenario:** store is locked (or no backup exists). User clicks Finish. `jobsRunNow` returns `locked`. `toast.error` runs, nothing renders, the user lands on Today with no run and no message. This is the exact silent failure AC3 forbids.

**Expected:** a translated error is visible on the screen the user lands on.
**Actual:** no visible output.

**Same gap elsewhere (merged FX4, out of FX14 scope):** the Kill Switch in `src/app/header/kill-switch/index.tsx:67` also calls `toast.error` with no `<Toaster>` in the app shell, so its failures are likewise invisible. Mounting one `<Toaster />` in the app shell fixes both.

**Fix:** mount `<Toaster />` once in the app shell (`src/app/`), not per feature. Add a test that does not mock `sonner`: render the shell, trigger the finish failure, and assert the message text is in the DOM. If you prefer an inline message, render it on the finish step instead, but then the step must stay mounted until the error is seen.

### F2 — MEDIUM: finish step states a login setting it could not read

- `src/features/onboarding/steps/finish/index.tsx:~97`: `autostart.data?.enabled ? hintOn : hintOff`.
- When `autostartStatus` fails, the value row shows "Could not read the launch-at-login setting", and the hint directly below reads "Boba opens only when you do." That is a claim about state the page does not know.

**Expected:** under a failed read, no claim about whether Boba opens at login.
**Actual:** the hint asserts "off".

**Fix:** when `autostart.isError`, drop the hint (or show only the link). Add a test: `autostartStatus` rejects, then assert neither `hintOn` nor `hintOff` text is present.

### F3 — LOW: a11y coverage is thinner than the AC asks

- AC4 asks for "keyboard-operable and labelled (e2e a11y)". No file under `e2e/a11y` covers Settings → Notifications, and the keyboard test in `index.test.tsx` only asserts `focus()`, not that Space toggles the box.
- The label and checkbox are correct as written, so this is a coverage gap, not a defect.

**Fix:** add the Notifications page (with the launch-at-login switch) to `e2e/a11y` if that suite already covers other Settings pages, or add a Space-key toggle test with `user-event`. If neither is feasible here, say so in the commit body and open a follow-up.

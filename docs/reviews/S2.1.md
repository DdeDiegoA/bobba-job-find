## Acceptance criteria

- **AC1** ✅ — `detect_all()` probes all 5 kinds (`claude_code, codex, opencode, gemini_cli, aider`) in parallel (`thread::scope`), each `--version` + `--help` bounded by a **2 s** per-subprocess timeout; worst case ≈ 4 s per CLI + ≈ 2 s once for the login-shell PATH lookup → well inside 10 s. Each `CliInstall` carries path, version, `HealthStatus` and the 6 probed capabilities (`stream_json, mcp, tool_allowlist, budget_flag, turn_flag, structured_output`), serialised to `capabilities_json`.
- **AC2** ✅ — missing CLIs are `CliStatus::NotInstalled { kind }` with `kind.install_url()`; `probe_path(kind, path)` lets the user add a binary by path (validated as an executable file).
- **AC3** ✅ — every driver test probes **recorded fixtures** via `include_str!` (`drivers/fixtures/*_help.txt`, `*_version.txt`); `detect` tests use a temp `#!/bin/sh` script. No real CLI or network in CI.

## Adversarial notes

- **Timeout handling is sound**: `run_capture` polls `try_wait`, kills on deadline, drains both pipes on reader threads so a full pipe cannot wedge the child; a hanging process returns `None` (tested, `run_capture_times_out_on_a_hanging_process`).
- **Path search**: login-shell `PATH` (`$SHELL -lc 'echo $PATH'`, 2 s bound) recovers nvm/volta/asdf/mise shims, then known locations. Non-interactive `-c` avoids `.zshrc` banners; low risk of stdout noise.
- **Windows**: `candidate_names` adds `.exe/.cmd/.bat`; `is_executable_file` returns true for any file on Windows (PATHEXT not consulted) — acceptable, the subsequent probe surfaces a non-runnable file as `Unhealthy`.
- **Aider** correctly probes as text-only (all capabilities false), matching ADR-010's tiering.
- **Store side**: migration `0002_cli_install.sql` is a real migration (first after `0001`), `STRICT`, `UNIQUE(kind, path)`; `upsert` keeps a stable `id` across re-probes (verified — second upsert returns the same id) and stamps `probed_at` in UTC. The S1.2a migration-chain guard tests stay green with a second real migration.

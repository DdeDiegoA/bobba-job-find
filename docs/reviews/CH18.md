## Root cause (from `gh run view 39082224414 --job 117542479528 --log-failed`)

`src-tauri/crates/boba-agent/src/supervisor/mod.rs` imported `process_wrap::std::ProcessGroup` unconditionally. In `process-wrap` 10.0.1 that item is gated on `all(unix, feature = "process-group")`, so on Windows it does not exist and the crate fails with `E0432 unresolved import process_wrap::std::ProcessGroup`. Linux and macOS were green.

## What changed on the branch

Two commits are on `hermad/CH18`. They were committed on the branch while this review ran, and their content matches what I checked. I did not add a code commit of my own.

- `bccfb32` — `ProcessGroup` import moved under `#[cfg(unix)]`, beside the existing `#[cfg(windows)]` `JobObject` import. Test helpers `wait_for_pid`, `alive` (`kill -0`), `until`, and the `std::fs` and `std::time::Instant` test imports gated `#[cfg(unix)]`. Their only callers are Unix-only tests, so on Windows they were dead code and `-D warnings` failed.

## Process-tree kill semantics

| Platform | Spawn wrapper | Kill call | Effect |
|---|---|---|---|
| Unix | `ProcessGroup::leader()` (child becomes group leader) | `start_kill` → `killpg(pgid, SIGKILL)` (`process-wrap` `process_group.rs:164`) | Kills the CLI and every process still in its group |
| Windows | `JobObject` (child assigned to job, created suspended, then resumed) | `start_kill` → `TerminateJobObject(job, 1)` (`job_object.rs:166`) | Kills every process in the job |

Both paths are reached from `SupervisedProcess::kill`, from `reap`/`wait` on the normal path, and from `Drop` when not yet reaped. Semantics match on both platforms: a cancel takes down the whole tree.

Gap: the regression test `kill_tears_down_the_whole_process_tree` is `#[cfg(unix)]`. Nothing exercises the Windows job kill in CI. See notes.

## Notes (non-blocking)

- No Windows test covers the job-object tree kill. Follow-up: a `#[cfg(windows)]` variant of `kill_tears_down_the_whole_process_tree` (e.g. the fake CLI spawns a child via `cmd /c ping` and writes its pid), so the Windows kill path has a test that runs on the Windows CI leg.
- The Windows `JobObject` does not set `KILL_ON_JOB_CLOSE`. A hard crash of the app leaves children running, as a crashed app on Unix leaves its process groups running. Not a regression. Record it in `docs/security/residuals.md` if the team treats orphaned CLI processes as a residual.
- `tools/fake-cli` default marker path `/tmp/boba-marker` is Unix-specific. Harmless today because all callers set `BOBA_FAKE_MARKER`. Could use `std::env::temp_dir()`.
- Two commits landed on this branch from another writer while I was reviewing. I verified the final content, not the authorship.

## Round 1 (927117d): changes requested

1. **Provenance spoof (AC4, medium).** `tracker_transition_status` passed the caller's `source` straight to the use case, so the UI could record a move as `status_proposal`, `apply_outcome` or `import`. Fixed in `d20120f`: the command accepts only `user` (`user_source`, `errors.tracker.source_not_allowed`), with a test covering all three forbidden sources.
2. **Stale board (AC4, low-medium).** `useTransitionStatus` re-read the board only on success, but `errors.tracker.stale` says "The board was refreshed". Fixed in `d20120f`: board and detail are invalidated in `onSettled`, with a test that a lost race re-reads the board.

## Acceptance criteria (at d20120f)

- **AC1** Nine columns in order, the four terminal ones collapsible; `status` is the stored truth and columns are derived in `boba-domain` (no UI-side status). Tests: `the_board_is_the_nine_columns_with_their_cards`, `only_the_four_terminal_columns_are_collapsible`.
- **AC2** Drag and `Cmd/Ctrl+←/→` both go through one `transition` call that writes a `status_event`; Undo is a second move; a move to Applied asks for confirmation. Tests in `board.test.tsx`.
- **AC3** Detail shows the Offer snapshot, the Package (verified flag from the documents owner), the timeline, next action and notes. Tests: `the_detail_shows_snapshot_package_timeline_and_notes`.
- **AC4** One writer (`TrackerService::transition`), domain rule (`can_transition`), race guard in SQL (`UPDATE … WHERE status = ?from`, rolled back on conflict), i18n error keys. Store tests: `a_move_that_races_lost_reports_the_status_it_found`, `a_move_updates_the_row_and_appends_the_event_in_one_transaction`.

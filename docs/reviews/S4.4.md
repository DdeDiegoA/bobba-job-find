## Defect found and fixed in this review

- **F1 (medium, fixed in `94b2274`)** — `merge_provenance` cleared `possibly_closed_at` on every re-sighting, including deadline closures. `finish_run` re-closed them, so a deadline-expired posting was reported as newly closed (with a moved timestamp) on every run that still listed it. The fix only clears the closure when the posting is not past its deadline. Regression test `a_deadline_closure_survives_a_resighting` exercises the real store path (the fake-repo test did not). Verified in `94b2274`.

## Non-blocking notes

- N1: `missing_runs` is per posting, but any sighting from any Source (`merge_provenance`) resets it. A posting dropped by a covered Source but still listed by an uncovered one never reaches *Possibly closed*. This reads as intended (it is still live elsewhere), so no change requested; worth stating in S5.1.
- N2: the `was_missing` branch in `finish_run` (loop 1) is effectively unreachable in production, because the merge already zeroes `missing_runs` before the sweep. Harmless; the reopen logic lives in `merge_provenance`.
- N3: the migration is `0018_posting_lifecycle.sql`, not the `0015` in the story. This follows the 2026-10-16 ruling (next free number on main); the 0015–0017 numbers are taken.

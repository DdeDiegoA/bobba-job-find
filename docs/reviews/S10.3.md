## Findings

### B-1 (blocker): the daily sweep is never scheduled

- `src-tauri/crates/boba-app/src/jobs/mod.rs:358` `default_schedules()` contains only `DailySearch`. Nothing in the diff adds a `RetentionSweep` slot. `tick` (`jobs/mod.rs` ~l.400) skips every job with no schedule, so `retention_sweep` is never due.
- `src-tauri/src/scheduler/mod.rs` `read_schedules()` returns the stored map as a whole once any schedule is saved. A user who saved a daily-search time therefore loses any retention default placed only in `default_schedules()`.
- **Expected:** a daily retention slot runs by default, and it survives a user-saved schedule.
- **Fix:** add a daily `RetentionSweep` default (e.g. 03:00 local) and merge defaults for any job the stored map omits. Test that (a) `default_schedules()` contains `RetentionSweep`, and (b) a stored `daily_search`-only JSON still yields a `RetentionSweep` schedule.

### Notes (no change required for approval)

- N-1: `retention/mod.rs` compares RFC 3339 strings lexically. A stored timestamp with fractional seconds that falls in the cutoff's own second sorts as older. Off by under one second at the boundary; acceptable.
- N-2: `commands/retention.rs` has no test. The handler's wiring (`register_handler`, port lookup, record) is untested; the sweep and store logic are covered. Adding one handler test after B-1 is welcome but not required.
- N-3: there is no UI to override the windows. The AC does not require one; the settings keys are in place for S10 Privacy work.

## What was checked and holds

- Offers with an Application are never deleted (`NOT EXISTS` guard). Raw payloads for them expire, the Application keeps its snapshot.
- Every FK that references `posting` or `email_message` is `ON DELETE CASCADE` (migrations 0008–0026), so the sweep cannot fail on an FK error.
- Applications, `document` and `audit_event` are not named by any statement; a test asserts it.
- `secure_delete=ON` is set on the production connection (`db/mod.rs:177`, `:189`).
- A second sweep deletes nothing (idempotent), which covers a retried slot.
- Settings: invalid, zero and oversized values fall back to the default instead of wiping or freezing data.

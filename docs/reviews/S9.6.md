## Findings

### F1 — daily caps count UTC days, not the user's local day (medium)

- `src-tauri/crates/boba-app/src/apply/rules/mod.rs` `counts()`: `day_start = now.replace_time(MIDNIGHT)` where `now` is the UTC clock.
- Active hours (`local_minute`) are local, so a user at UTC-5 gets a "day" that resets at 19:00 local. The 5/25 daily caps and the global 10 are then counted over the wrong window. A user can exceed the daily cap in one local day.
- Expected: the daily window starts at local midnight, the same clock the active hours use.
- Repro: `now = 2026-10-17T02:00:00Z`, user offset −05:00. Local day started 2026-10-16T05:00Z; the code counts from 2026-10-17T00:00Z. Auto attempts from 16:00–20:00 local on 2026-10-16 are not counted.
- Fix: compute `day_start` in local offset (`time::UtcOffset::current_local_offset()` or the offset already used by `local_minute`), and add a test with a non-UTC offset.

### F2 — stored spacing bounds are never enforced (low)

- `AutoSettings.spacing_min_minutes` / `spacing_max_minutes` are persisted, validated (`settings.rs` `validate()`), and returned in `RulesSnapshot`. `decide()` ignores them and uses the fixed `pace::gap_minutes` 5–20 constants.
- No service method sets them, so the values are always the defaults or hand-edited rows. Dead config that looks live.
- Expected: either wire `gap_minutes` to the settings range, or drop the fields until a setter exists.
- Fix: pick one. The AC fixes the range at 5–20, so dropping the fields is the smaller change.

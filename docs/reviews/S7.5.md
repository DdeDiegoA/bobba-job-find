## Checks done by reading

- `count_orphans` reads the last `Text` item of each page (recursing into groups). The templates (`templates/cv/classic.typ`, `modern.typ`) have no footer, header, or uppercase transform, so the heading text reaches the frame verbatim. Confirmed.
- `Slot::remove` drops a section when its last item goes, so the fit itself cannot strand a heading. Indices are recomputed each loop, so removing one section does not shift a stale index.
- Termination: each iteration removes one slot; with no slots left it returns `CannotFit`. No division by zero in `jaccard` (early return when shared == 0). `uniqueness` uses `ptr::eq`, so two identical lines in different slots each count the other.
- No panic paths on the fit path: `weakest` returns `None` on any out-of-range index instead of indexing.

## Non-blocking notes

- **N1.** `fit_cv` loops on `pages > budget` only. A fitted CV that is within budget can still carry `report.orphans > 0` (a heading stranded when a non-last line was cut). `FitOutcome` documents this and says the studio flags it (S7.7). Acceptable for this slice; S7.7 must surface it.
- **N2.** The cover letter has no cut path: `cover_fits` returns `false` and the caller must decide. AC2 is met as a check. The producing use case (S7.7 / the studio) must handle a `false` result, not ignore it.
- **N3.** `fit_cv` and `verify_cover` have no production caller yet. `relevance` is caller-supplied until S6.3. Expected; not a defect in this slice.
- Orphan detection matches by text equality (documented shortcut in the code): a body line whose whole text equals a heading would be miscounted. Low risk with the current templates.

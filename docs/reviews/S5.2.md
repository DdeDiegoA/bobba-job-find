## Residuals (not blocking, follow-up)

- R-S5.2-1 (low): `score()` checks `new_ids.iter().any(...)` for every seen Offer, which is O(seen × new). A `HashSet` fixes it. Matters only at large inboxes.
- R-S5.2-2 (low): `merge_retry` sums `duration_ms` of the first run and the retry. That is work time, not wall clock. Label it or compute wall clock from `started_at` / `finished_at`.
- R-S5.2-3 (low): `LiveSources::search` reports a failed row read as `SourceFetch::Err { source_id: "sources" }`. The placeholder id should be the Source being searched.
- R-S5.2-4 (low): when a newer run took over, a retry is stored on its own. Its totals show only the retried Sources. The UI copy should say so; the behaviour is intended.
- R-S5.2-5 (low): `score()` still runs gates and feature reads for every seen Offer on every run, as the cache-first design allows. Watch it in the S9.x performance pass.

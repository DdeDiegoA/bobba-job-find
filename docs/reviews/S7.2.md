## Findings

### F1 — claims without `fact_ids` are accepted and stored (AC2) — must fix
- **File:** `src-tauri/crates/boba-domain/src/documents/mod.rs:195-203` (`Claim`), and `src-tauri/crates/boba-docs/src/lib.rs:146-159` (test).
- **Failure scenario:** the agent saves a CV whose bullet is `{"text": "Led the billing team"}` with no `fact_ids`. It deserializes with an empty list and `save_drafts` stores it as a normal draft. Nothing rejects it in this slice, so a fabricated claim lands in the studio. The `S7.3` validator is not in S7.2's file list.
- **Test mismatch:** `a_claim_without_facts_serialises_as_an_empty_list_not_a_missing_field` asserts the field is **missing** (`get("fact_ids").is_none()`). The name says the opposite.
- **Expected:** every claim item always serializes `fact_ids` (an array, possibly empty), and deserializing an item without `fact_ids` fails.
- **Fix:** drop `#[serde(default)]` and `skip_serializing_if` from `Claim.fact_ids` so the field is required. Rename or rewrite the test to assert `fact_ids` is present as `[]` on serialize, and add a test that a claim missing `fact_ids` fails to deserialize.

### F2 — the language fallback must reach the production path (AC1) — must fix
- **Orquestador ruling (2026-10-16):** `fallback_from` must be surfaced by S7.2's production path: persisted on the generated document record, and returned in the tailor command/event payload (typed, in bindings). The visible UI notice lands in S7.7 (Studio).
- **File:** `src-tauri/crates/boba-app/src/tailoring/mod.rs:62-70` (`save_drafts` takes `lang: Lang`, drops the `LanguageChoice`); `src-tauri/crates/boba-store/src/repos/documents.rs` (no column for the reason).
- **Expected:** the fallback reason is stored on the document rows and returned from the tailor command/event payload with a typed field (specta-exported, `bindings.ts` regenerated).

### F3 — informational
- `save_drafts` has no production caller yet (only tests). The `untrusted_origin = 1` and `fact_ids` guarantees are unit-tested but not exercised end to end. Acceptable for S7.2 if the tailor-run slice calls `save_drafts`. Not a blocker.

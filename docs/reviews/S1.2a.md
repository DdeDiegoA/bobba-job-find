## Acceptance criteria

- **AC1** ✅ — `first_launch_mints_256bit_key_in_keychain` (64-char hex stored at `service/db-key`), `db_file_is_not_readable_with_plain_sqlite` (plain SQLite → `NotADatabase`). Verified in the tests and by reading `keys::load_or_create`.
- **AC2** ✅ (logic) — `pre_migration_snapshot_is_encrypted_owner_only_and_same_key` (0600, same key, unreadable without key), `migration_refused_when_free_disk_below_twice_db_size`, `snapshots_deleted_after_three_launches_and_fourteen_days` ("whichever comes later": both conditions required). Snapshot is `VACUUM INTO` on the keyed connection → same key.
- **AC3** ✅ — `writer_serialises_writes_and_read_pool_reads` (8 concurrent writers, all land), `crash_mid_write_leaves_db_consistent` (child aborts mid-transaction; `integrity_check=ok`, committed row present, uncommitted row absent).
- **AC4** ⚠️ — discovery by sorted file name works (`build.rs` + `migrations_are_discovered_by_sorted_file_name`), **but** it also discovers 19 placeholder files — finding 1.
- **AC5** ✅ — existing DB + unreadable key → `KeyError::Locked`; `existing_db_without_readable_key_is_locked_and_never_mints` also asserts the key was not re-minted and the DB size is unchanged. Wrong key → `StoreError::Locked`.

## Adversarial notes on key custody (positive)

- The key is applied as the **first** statement on every connection (`apply_key`, `with_init`), and `open_encrypted` proves it by touching `sqlite_master` before anything else — a wrong key surfaces as `NotADatabase` → `Locked`, never corruption.
- `load_or_create` never mints over an existing DB, and `DbKey` is `Zeroizing` with a redacting `Debug`. The `PRAGMA key` value is hex-only (no injection surface through `format!`).
- Writer actor: one thread owns the write connection; `Drop` drops the real `Sender`, the actor drains, then joins. No shared `Connection` behind a mutex.

## Finding 1 — P1 · placeholder migrations poison the chain (blocker)

**Evidence (reproduced):** `build.rs` embeds every `migrations/*.sql` (`sort()`), and `migrations/` contains `0001_init.sql` plus **`0002`–`0020` comment-only placeholders** committed by S1.1 (`-- Placeholder migration (S1.1)…`). A throwaway probe against `boba_store::migrate::embedded()` printed:

```
PENDING_BEFORE=20
USER_VERSION_AFTER=20
```

(The probe file was removed; the worktree is clean.)

**Why it's wrong:** `rusqlite_migration` counts every embedded `M::up(...)` as a migration and advances `PRAGMA user_version`. On a fresh DB the app now records **version 20** after creating only the real `0001` schema. When a later slice fills `0002_cli_install.sql` (its own `files`), `pending_migrations` for that DB is **0** → the migration is a silent no-op and the table is never created. It also breaks the AD-20 "never edit once shipped" rule for all 19 files. Existing tests pass because placeholders execute fine and no test asserts the resulting `user_version`.

**Impact:** latent schema corruption for every DB slice after S1.2a (S2.1, S4.1, S7.1, S10.x…). Given S1.2a is a gated DB slice, this must be fixed before merge.

**Fix:**
1. Delete `migrations/0002_cli_install.sql` … `0020_status_proposals.sql` (19 files), leaving only real migrations (`0001_init.sql` now). Each later slice adds its own `NNNN_name.sql` — which is exactly pm's "migrations are never pre-stubbed" convention.
2. Add `migrations/**` (not just `0001_init.sql`) to S1.2a's `files` so this cleanup is in scope (pm).
3. Add a guard test so it cannot recur, e.g. assert `embedded()` contains no SQL whose first non-blank line starts with `-- Placeholder`, and/or assert `user_version == embedded().len()` after `apply` on a fresh DB.

They are only transitively in `Cargo.lock`. **Fix:** move them to `[workspace.dependencies]` (needs the root `Cargo.toml` in S1.2a's `files`, or a pm/orquestador call). Low risk, but it is the convention the reviewer is asked to enforce.

## Finding 3 — P3 · files outside S1.2a `files`

## Bug found and fixed in review

- **BUG 1 (AC1, FR-77), fixed.** `reading_order` searched each block from the start of the layer, so a heading whose word also appears in an earlier block (the summary contains "experience") was placed at that earlier occurrence. A layer where the heading prints after its item passed with `out_of_order = []`.
  - Fix: a cursor-based match. An occurrence counts only if it ends after the previous block ended, and a block found only before the cursor is reported.
  - Regression test: `a_word_that_also_appears_in_the_prose_does_not_hide_a_swapped_block`.
  - Note: the dev reports the flagged block as the item (`"Shipped the billing pipeline in Rust"`) rather than the heading. Under any positional rule the item is the block shown before its time, so the item is accepted as the flagged block. The check fails either way.

## Acceptance criteria

- **AC1 (FR-77): pass.** `text_layer_facts` reads the rendered PDF's own text layer and checks literal contact fields, reading order, `(cid:` and U+FFFD, and every backed keyword. An unreadable layer returns `VerifyError::Measure`, which is an error, not a pass. Tests cover a passing CV and cover letter, a missing contact field, a cover letter not asked for headline or links, a backed keyword missing from the layer, the swapped-block regression, undecodable markers, and an unreadable PDF.
- **AC2 (FR-75): pass.** `keywords::coverage`, `backed_keywords`, and `gaps` return keywords with a verdict. `backed_keywords` never returns a gap, so a caller cannot insert one by accident. The panel lists each requirement as covered or a gap, names the gaps as "not added", and tags the non-inserted keywords with `data-not-inserted`. The panel never matches keywords itself.
- **AC3: pass.** `verify_document` combines layout, ATS, and fabrication. `VerificationReport::is_verified(kind, budget)` requires all three: `layout_passes` (no orphans, one page for a cover letter, within budget for a CV), `text_layer.passed()`, and `fabrication_ready`. The end-to-end test uses the real renderer, layout pass, and validator.

## Non-blocking notes

- **N1.** `VerifyPort` is not mounted in `wiring/port_list.rs`, and `is_verified` has no production caller yet. The dev and orquestador agreed the mount and the verdict gate belong with S7.7. This is consistent with the story scope, but S7.7 must wire `is_verified` before any document is attached to a submission.
- **N2.** `pdf_extract::extract_text_from_mem` can panic on some malformed PDFs. The input here is always a PDF this process just rendered, so the risk is low. If the input ever widens (a user-supplied file), wrap the call in `catch_unwind` or validate first.
- **N3.** `missing_contact` and `reading_order` compare folded substrings, so a contact value that happens to be a substring of other text would pass. The contact values are full names, emails, and URLs, so the practical risk is low.

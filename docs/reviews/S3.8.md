## Findings

### F1 — medium — fail-open on recovery gate (ADR-009)
- **File:** `src-tauri/src/scheduler/mod.rs:155-161`
- **What:** `recovery_backup_required` maps a port that exists but whose `status()` errors to `false` (`.map(...).unwrap_or(false)`). A backup-status read error lets a Search Run start with no recovery backup.
- **Repro:** mount a `BackupPort` whose `status()` returns `Err`; call `run_now` or let `tick` fire. The run proceeds.
- **Expected:** when the port is mounted and its status is unreadable, the gate is closed (`unwrap_or(true)`). Only a missing port (tests/headless, `Err` from `wiring::port`) stays open.
- **Fix:** change `unwrap_or(false)` to `unwrap_or(true)` and add a test with a `BackupPort` whose `status()` errors.

### F2 — medium — completion not enforced in core (AC3)
- **File:** `src-tauri/src/commands/onboarding.rs:54-66` (`complete`), `src/features/onboarding/steps/backup/index.tsx:14-16, 44-45`
- **What:** `onboarding_complete` records completion without checking the backup. The only gate is the UI validator `backupStepIsValid(answers.recoveryPresent)`. That answer is persisted through `saveProgress` (localStorage). A restored `recoveryPresent: true` is valid before `backup_status` resolves and the mirror effect corrects it, so Next can finish without a backup. The core then marks onboarded.
- **Repro:** finish the wizard to the backup step with a stored progress that has `recoveryPresent: true` and no backup on disk; click Next before the backup status query resolves. `onboarding_complete` runs and the gate opens. Search runs stay blocked by F1's gate, so the damage is limited to a setup that claims to be finished.
- **Expected:** AC3 says "before I can finish". Enforce it in the core: `complete` checks the backup status and returns `errors.backup.recovery_required` (conflict) when `recovery_required`. Keep the UI gate as the fast path.
- **Fix:** inject the `BackupPort` (or the status read) into `onboarding_complete`, refuse with the existing `errors.backup.recovery_required` key, and add a test that a completion without a backup is refused and leaves no `onboarding.completed_at` row.

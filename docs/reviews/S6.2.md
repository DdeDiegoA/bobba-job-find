## Findings

### 1. LLM-proposed features are stored without provenance `{agent_run_id, cli, model}` (AD-5)

- **Where:** `src-tauri/crates/boba-store/migrations/0014_posting_features.sql` (table `posting_features`, columns `source` and `confidence` only). `src-tauri/crates/boba-app/src/posting_features/mod.rs` `store_proposal` (around line 259) writes claims without any run identity.
- **What happens:** an `llm` row can be traced to "an agent proposed this" but not to the run, CLI, or model that proposed it. AD-5 requires every agent output to carry `{agent_run_id, cli, model}`, and AC1 requires "Both are stored with provenance." A later audit or re-score cannot tell which run produced a claim.
- **Expected:** add provenance for `source = 'llm'` rows. Either three nullable columns on `posting_features` (`agent_run_id`, `agent_cli`, `agent_model`, required when `source = 'llm'` via CHECK), or a `posting_features_run` row keyed by run id that the claims reference. Pass the run id, CLI and model from `AgentTask` / the run handle into `harvest` and `store_proposal`. Add a test that an `llm` claim round-trips its run id, CLI and model.
- **Severity:** medium (blocks AC1 as written and AD-5).

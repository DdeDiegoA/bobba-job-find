## Security checks

- **Scope (AC1, NFR-5): pass.** The bundled Gmail client requests `https://www.googleapis.com/auth/gmail.send` only (`gmail/mod.rs:42-47`). A test asserts the authorisation URL never contains `readonly` (`gmail/mod.rs:405-433`). No `gmail.readonly` or `offline_access` is requested.
- **Loopback + PKCE + state: pass.** Reuses the S8.1 `PendingFlow` and loopback code, so the S8.1 checks still hold for Gmail.
- **No secret in the repo: pass.** `BOBA_GMAIL_CLIENT_ID` and `BOBA_GMAIL_CLIENT_SECRET` are read only through `option_env!`. No `.env` file is tracked, and no literal secret appears in the diff.
- **Secret never in the authorisation URL: pass.** `with_client_secret` is used only at the token endpoint (`oauth/mod.rs:323`). A test asserts `client_secret` is absent from the authorize URL (`oauth/mod.rs:726`).
- **Secret storage: pass.** `GmailSecret` is stored as one keychain entry per connection. Its `Debug` impl redacts both tokens and the client secret (`gmail/mod.rs:53-66`).
- **IMAP read-only (AC2): pass at the adapter level.** The IMAP probe uses `EXAMINE INBOX` only, and a test asserts the mailbox is opened read-only (`imap/mod.rs:303`). No `STORE`, `APPEND`, `EXPUNGE` or `COPY` appears in the diff.
- **TLS: pass.** IMAP and SMTP use `native-tls` with the default certificate validation. No `danger_accept_invalid_certs` or equivalent.
- **Dependencies: pass.** `lettre`, `async-imap`, `native-tls` and `tokio-native-tls` are already in the lock or pinned in `Cargo.toml`. `cargo deny` passes with no change to `deny.toml`.
- **IPC surface: pass.** One line added to `command_list.rs`. The command returns `ConnectionView` only, with no tokens or secrets.

## Findings

### F1 (blocking, AC2): IMAP/SMTP connection test and save are not reachable from the app

- Files: `src-tauri/crates/boba-mail/src/imap/mod.rs:121` (`test_connection`), `src-tauri/crates/boba-mail/src/smtp/mod.rs:114` (`test_connection`).
- Expected (AC2): "Given an IMAP/SMTP account (app password or XOAUTH2), when I save, then a connection test runs first."
- Actual: `test_connection` exists in both adapters, but no command, `command_list.rs` entry, or frontend file calls it. `grep` over `src-tauri/src` and `src/` finds no reference to `imap::`, `smtp::`, `ImapSettings`, or `SmtpSettings`. No account can be saved through IMAP or SMTP, so AC2's "when I save" can never run.
- Repro: Build the app. There is no IPC call that accepts IMAP or SMTP settings, so the probe is unreachable.
- Action: Either (a) add the save command, which runs `test_connection` before persisting and refuses on failure, with one `command_list.rs` line and a test that a failed probe persists nothing, or (b) orchestrator confirms the save path belongs to a later story (S8.3/S8.4) and S8.2 is adapter-only. Under (b), the AC2 text must be marked as deferred in `stories.yaml` before merge.

### F2 (non-blocking, correctness): BYO client id is accepted without its client secret

- File: `src-tauri/src/commands/email.rs:288-296` and `src/features/connections/email/index.tsx:308-315`.
- Failure scenario: The user enters a BYO client id and leaves "Advanced: your client secret" empty. `client_secret` becomes `None`, so the token request goes out without `client_secret`. Google rejects it at the token endpoint, and the user sees a generic connect failure with no hint that the secret is missing.
- Expected: Require the secret when a BYO client id is supplied (reject before the browser opens with a specific key such as `errors.email.byo_secret_missing`), or document and surface the Google error.
- Test gap: no test covers the BYO branch with a missing secret.

### F3 (non-blocking, build config): bundled id set but bundled secret unset

- File: `src-tauri/src/commands/email.rs:295` (`ClientIdKind::Bundled => BUNDLED_GMAIL_CLIENT_SECRET.map(...)`) and `:350-353` (`bundled_or_byo`).
- Failure scenario: A build sets `BOBA_GMAIL_CLIENT_ID` but not `BOBA_GMAIL_CLIENT_SECRET`. The bundled path is selected and the token exchange fails at Google.
- Expected: Treat the bundled path as unavailable unless both values are present, so the UI offers BYO instead. This matters for S10.5 registration.

## Residuals for Diego (security gate)

1. **Bundled Google client secret is embedded in every binary.** It comes from `option_env!` at build time. Google documents the installed-app secret as not confidential, so this is the usual pattern. But the story text says "no confidential secret", and the value does ship with each binary. Diego to accept, or to decide a mitigation (for example, rely on BYO-only until a release registration exists).
2. **Live OAuth is not exercised.** All Gmail token and send paths are tested with wiremock. Google's behaviour with `gmail.send` alone (no `offline_access`, refresh token issued to installed apps) must be verified once against a real registered client. This is part of S10.5 at the latest.
3. **Per-connection copy of the client secret** sits in the keychain entry next to the tokens (AD-13). Accepted by design; it is not a new exposure beyond the tokens already stored there.

## Requested changes for dev-4

1. F1: wire the IMAP/SMTP save path with probe-before-save, or get the orquestrator's scope ruling and mark AC2 deferred in `stories.yaml`.
2. F2: require the client secret for BYO, and add a test for the missing-secret case.
3. F3: make the bundled path require both values.
4. Re-run the full gate and re-commit. Reviewer-4 re-reviews on the new commit.

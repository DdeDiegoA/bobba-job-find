## Blockers and findings

### B-1 (blocker): check-i18n red — a `#[cfg(test)]` at the top of the file hides `message_key`

`src-tauri/crates/boba-app/src/stats/mod.rs:23` has `#[cfg(test)] pub mod testing;`. `scripts/check-i18n.mjs` takes the production part of a file as everything before the first `#[cfg(test)]`, so it cuts the file at line 23. `StatsError::message_key()` (line 59) is then invisible, and `errors.audit_stats.store` is reported unused in both `locales/en/errors/audit_stats.json` and `locales/es/errors/audit_stats.json`.

- **Repro:** `node scripts/ci/check-i18n.mjs` at `1b3de0a` → exit 1 with the two `unused key` lines.
- **Fix:** move `#[cfg(test)] pub mod testing;` to the bottom of `stats/mod.rs`, next to `#[cfg(test)] mod tests`. Re-run check-i18n and confirm `i18n ok`.

### M-1 (medium): the viewer silently drops Auto decisions after 500

`src-tauri/crates/boba-app/src/stats/audit.rs:32` caps `OUTBOX_LIMIT = 500`, and `outbox_entries` applies it. AC-1 says the viewer shows every Auto decision, and the CSV is "the whole log". Past 500 outbox items the oldest decisions disappear from both the viewer and the export, with no notice.

- **Expected:** every Auto decision is listed and exported (AC-1).
- **Fix:** read all outbox items (drop the cap, as `audit_rows` already does). If a cap stays for cost, the view and the CSV must show an explicit "newest N of M" notice.

### M-2 (medium): CSV formula injection

`src-tauri/crates/boba-app/src/stats/audit.rs` `csv_field` only doubles quotes. Fields include source names (from user-defined and ATS sources), outbox notes and `detail_json`. A value that starts with `=`, `+`, `-`, `@`, tab or CR runs as a formula when the CSV opens in Excel, Numbers or Sheets.

- **Repro:** a source named `=HYPERLINK("https://x","open")`, then Export CSV, then open the file in a spreadsheet.
- **Fix:** in `csv_field`, prefix a single `'` to values that start with one of those characters, then keep the RFC 4180 quoting. Add a test next to `csv_escapes_commas_and_quotes`.

### M-3 (medium): the intro overclaims the chain

`locales/en/audit_stats.json` `audit.intro` says "The log is hash-chained; nothing here can be edited." Only the `audit_rows` (send, kill switch, and so on) are chained. Stage changes come from the mutable status history, Auto decisions from the mutable outbox (state changes), and opt-ins from the sources table. The banner "Hash chain verified across N rows" is accurate only for the chained rows.

- **Fix (EN and ES):** scope the sentence, for example "Sends and Kill Switch events are hash-chained. Stage changes, decisions and opt-ins are read from the app's records." Keep `audit.chain.ok` as is, or name the chained rows.

### L-1 (low, follow-up): cost and pagination

`entries()` loads every audit row, and `stage_entries` and `funnel()` each run one `status_events` query per application (N+1). Pagination is client-side, so the IPC payload is the whole log on each render. Fine at MVP scale. Track as a follow-up: paginate in SQL and batch the status history.

### L-2 (low, residual): `detail_json` is shown verbatim

`audit/index.tsx` renders `detail_json` in a `<details>` block and in the CSV. The session-board failure path writes `error.to_string()` of transparent wrapped errors into the detail (`boba-sources/src/session/sdk/service.rs:415`). The payload builders I read carry no cookies or tokens. I did not verify every wrapped error's text. Confirm in the fix round or accept as residual.

### L-3 (low): the export command takes any path

`audit_log_export_csv` writes to the `destination` string it receives. The UI passes the native save-dialog path, so this is safe in practice. Note only; no change required.

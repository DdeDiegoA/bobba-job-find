### Condition 1 (blocks S7.7's review loop, not this merge)

`save_review` takes `app_id` from the agent's arguments. `RepoTools::call`
receives only the run's task id, and `AgentTask` carries no application id, so
nothing binds the critique to the application the review run was started for. A
review run that reads injected posting text could write a critique onto another
application's drafts. Impact is limited: only `review_json` is written, the
drafts are untouched, and the studio renders the text as data (ADR-010). No
review run exists before S7.7, so nothing is exposed yet.

**S7.7 must:** record the application id when it starts a review run, and have
`save_review` refuse any other `app_id` (a test that a foreign `app_id` is
refused). This must land before the review loop goes live.

### Condition 2 (S7.7 display)

`save_critique` annotates the **newest** version of each kind at review time.
The revision run then saves a newer version with no critique, so a studio that
reads only the latest version shows no findings after a revision. The
tailor skill says the user can still read the version the reviewer commented
on. **S7.7 must decide** which version the studio shows the critique against,
and test it, before the findings can appear in the studio.

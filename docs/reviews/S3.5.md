## Findings

### F1 — major: `profile_import_start` blocks the IPC thread for the whole agent run

- **File:** `src-tauri/src/commands/profile_import.rs:109`
- **What happens:** the command is a plain `pub fn`. It calls `service(&app)?.start(...)`, which runs `agents.run` and waits on `handle.events` until the run ends (up to `RUN_WALL_CLOCK`). Tauri runs sync commands on the main thread.
- **Impact:** a multi-minute CV import freezes the whole window (no repaints, no clicks, no cancel). Every sibling command that runs an agent is async and offloads with `spawn_blocking`: `agent_test_call` (`commands/agent.rs:418`), `studio_edit` (`commands/studio.rs:180`), `apply_ats_start` (`commands/apply.rs:335`).
- **Expected:** make it `pub async fn`, wrap the `read_files` + `chosen_engine` + `start` work in `tauri::async_runtime::spawn_blocking`, and map the join error to an `AppError` the same way the siblings do. Keep the signature otherwise unchanged so the bindings stay stable.

### F2 — medium: PDF text extraction has no decompressed-size cap

- **File:** `src-tauri/crates/boba-app/src/profile_import/extract.rs:156` (`pdf_text`), reached from `extract_raw` for direct PDFs and from `zipped_text` for PDFs inside a LinkedIn ZIP.
- **What happens:** the 20 MB file cap applies to the compressed bytes only. `pdf_extract::extract_text_from_mem` inflates FlateDecode streams with no output bound. A small, hostile PDF can expand to many gigabytes. `catch_unwind` does not help: an allocation failure aborts the process and is not a panic.
- **Impact:** the app can be OOM-killed by one imported file. The brief asked for zip-bomb caps, and a PDF bomb is the same class of problem.
- **Expected:** one of: (a) pre-scan the PDF with `lopdf` (already a dev-dependency; promote it if needed) and refuse when the summed decoded stream size exceeds a cap, with a test built from a deflate-bomb PDF; or (b) if the dev judges (a) disproportionate, record it as a documented residual in `docs/reviews/S3.5.md` and in the S3.5 slice notes so the orquestador can decide. Recommendation: (a).

### F3 — low: the IPC command accepts any path string

- **File:** `src-tauri/src/commands/profile_import.rs:115` (`profile_import_start`, `files: Vec<String>`)
- **What happens:** the UI picks files with `@tauri-apps/plugin-dialog`, but the command reads whatever path it is given (`read_files`, up to 20 MB each) and sends the text to the agent. A compromised webview could read any file the user can read.
- **Expected:** narrow the risk, e.g. accept only paths the dialog granted (dialog scope) or record it as accepted residual. This is hardening, not a blocker on its own.

## Nits

- `extract.rs`: `zipped_text` silently skips entries that fail `by_index` or `read_to_end` (`continue`). Fine for LinkedIn exports; a one-line comment saying why would help.

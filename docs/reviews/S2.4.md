## Verified by reading and by tests

- **Observation is per run.** The init event is parsed (`drivers/claude_code.rs`); `lockdown::init_event_is_locked_down` accepts only `mcp__boba__*` names and an empty list fails. The runtime kills an untrusted run on a native tool before any tool result (`runtime/mod.rs`, init check). Nothing is cached across runs.
- **Abort before the CLI acts.** The init event is the first stream line, before any model turn. `--tools ""` (from `lockdown::pinned_args`) removes the built-in tools, so a race between kill and first action has no native tool to use. Pinned args reach production argv through `wiring/agent.rs`.
- **Missing init is fail-closed** for untrusted tasks on success (post-loop check) and on stream content without init (in-loop check). Tests: `a_silent_cli_that_exits_clean_is_refused_for_an_untrusted_run`, `an_untrusted_run_without_an_init_event_stops`.
- **Other CLIs stay refused.** Codex, OpenCode, Gemini and Aider have no pinned config (`pinned_args` returns `None`) and no init-tools accessor. Untrusted tasks on them return `Unsupported`.
- **`--tools ""` matches the recorded fixture.** `drivers/fixtures/claude_code_help.txt` documents `--tools`; the flags are tested against it in `the_pinned_lockdown_flags_are_the_ones_the_cli_documents`.
- **Output validation.** `tasks/output.rs` checks outputs against the `boba-mcp-proto` catalog schemas; the catalog uses `additionalProperties`, `items` and `minimum`, and any other keyword fails closed. Two refusals are retried; the third fails the run (`mcp/server.rs`, `an_invalid_output_is_retried_and_then_fails_the_run`), and `failed_output` stops the CLI (`runtime/mod.rs`).
- **Render into the workspace in production.** `pack::write_into` is called from `runtime::furnish` for every run, writing `CLAUDE.md`, `AGENTS.md` or `GEMINI.md` with `target_language` filled in and a provenance footer (pack version, CLI, model).

## Verified by reading and by tests

- **Observation is per run.** The init event is parsed (`drivers/claude_code.rs`); `lockdown::init_event_is_locked_down` accepts only `mcp__boba__*` names, and an empty list fails. The runtime kills an untrusted run on a native tool before any tool result (`runtime/mod.rs`, init check). Nothing is cached across runs; the gate (`wiring/agent.rs::lock_down`) only decides whether an untrusted task may start.
- **Abort before the CLI acts.** The init event is the first stream line, before any model turn. `--tools ""` (from `lockdown::pinned_args`) removes the built-in tools, so a race between kill and first action has no native tool to use. Pinned args reach production argv through `wiring/agent.rs`. Test: `an_init_event_with_a_native_tool_aborts_an_untrusted_run` asserts no tool call or result precedes the abort.
- **Missing or unverified init is fail-closed** for untrusted tasks: the in-loop check for a stream that opens without init, the post-wait check for any run that never opened, with the auth/quota carve-out. Tests: `a_silent_cli_leaves_an_untrusted_run_unverified` (`silent`, `silent-fail`), `an_unverified_run_reports_itself_unverified_whatever_the_exit`, `an_untrusted_run_whose_stream_never_opens_with_its_init_event_stops`.
- **Other CLIs stay refused.** Codex, OpenCode, Gemini and Aider have no pinned config (`pinned_args` returns `None`) and no init-tools accessor. Untrusted tasks on them return `Unsupported`.
- **`--tools ""` matches the recorded fixture.** `drivers/fixtures/claude_code_help.txt` documents `--tools`; the flags are tested against it in `the_pinned_lockdown_flags_are_the_ones_the_cli_documents`.
- **Output validation.** `tasks/output.rs` checks outputs against the `boba-mcp-proto` catalog schemas. The catalog uses `additionalProperties`, `items` and `minimum`; any keyword the checker does not implement is refused. Two refusals are retried; the third fails the run (`mcp/server.rs`, `an_invalid_output_is_retried_and_then_fails_the_run`), and `failed_output` stops the CLI (`runtime/mod.rs`).
- **Render into the workspace in production.** `pack::write_into` is called from `runtime::furnish` for every run, writing `CLAUDE.md`, `AGENTS.md` or `GEMINI.md` with `target_language` filled in and a provenance footer (pack version, CLI, model).
- **Stored per run.** `agent_run.pack_version` (migration 0011) is written with `cli` and `model` in `start_run`; the repo test round-trips all three.

## Residuals to track

1. The version-only pass in `lockdown::support` for Claude depends on the pinned config being in place for that version. ADR-010 §1 already requires re-verification when a CLI updates; that stays in the driver's verified-range check.
2. An auth or quota failure on a silent untrusted run keeps its failure reason (by design, FR-21). It is the only path where a run that never showed its init event reports something other than `Unsupported`.
3. The `boba-mail` Graph test flake (S8.1) is not S2.4 code; the orquestador logs it as a chore.

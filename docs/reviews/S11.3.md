## Findings

**F1 (medium, AC3): apply-side challenge pauses Auto without notifying the user.**
- Failure scenario: a CAPTCHA appears while the user is filling a Session Board form in the apply window. `SessionApplyService` records the challenge, sets `source.paused_until` to now+7d, and returns. No `SessionChallengePaused` notification is sent, so the user is not told Auto is paused; the only signal is Settings → Auto.
- Expected (AC3): "then Auto pauses for that Source for 7 days and I am notified."
- Actual: no notifier in `SessionApplyService` (`apply/session/mod.rs` has no `notifier` field); the run-side path is the only one that notifies.
- Suggested fix (dev-2's call): give `SessionApplyService` an `Option<Arc<dyn NotifierPort>>` the same way `boba-sources` `SessionBoardService` does, wire it in `src/wiring/session.rs`, and after the audit outcome call `notifier.notify(Notification::SessionChallengePaused)` with the AD-21 "never undoes the pause" ignore. Add a test that a challenge on the apply path notifies once.
- Not a security-gate exception: no permission or crypto change.

## Residuals (for Diego, security gate)

- **R1 — no automatic board submit in this build.** The Outbox sweep runs `decide()` on a Session Board item at release, then parks it `channel_unavailable`; the browser port never presses a board's submit (AD-11). Auto is therefore enforced at the decision point but cannot send yet. Matches dev-2's residual (1).
- **R2 — `OutboxService::enqueue` has no production caller** (S9.7 R1). "Attempt creation" enforcement goes through the same `candidate_for`/`decide()` seam, not through enqueue. Carry to the wave that wires the Outbox.
- **R3 — duplicate constant.** `session_policy::MIN_HOLD_MINUTES = 60` duplicates `outbox::SESSION_BOARD_MIN_HOLD_MINUTES = 60`. Both are 60 today; they should resolve to one source of truth before the next change.
- **R4 — apply-side challenge does not disable the reading Source** (run side does, AD-10). Pre-existing on the apply path; out of S11.3 scope but relevant to "the user acts, never Boba".

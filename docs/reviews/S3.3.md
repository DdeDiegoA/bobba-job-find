## Core enforcement (orquestador focus point)

- The snapshot is read-only. It is computed by `boba_app::capabilities::snapshot` from the chosen engine and the probe verdict, and never widens what a run may do.
- Availability is taken from the same function as the S2.4 per-run gate (`lockdown::support`). Test `capability_availability_never_disagrees_with_the_per_run_gate` asserts equality for every task-bearing capability on claude_code / aider / codex.
- Limited mode (no stored choice, not installed, or unhealthy) turns every AI capability off with `NoAgent`. Deterministic capabilities stay on. Test `limited_mode_blocks_every_task_a_run_would_otherwise_dispatch`.
- S2.4 is untouched by this slice. The run paths refuse without a stored engine (`ingest::trigger_extraction`, `profile_import` `NoEngine`, studio `NoEngine`), and the runtime `held_back` still refuses untrusted tasks with no gate mounted.
- The UI fails closed: an unknown or unloaded capability reads as unavailable with no reason, so no CTA is shown.

## Acceptance criteria

- AC1 (limited mode keeps deterministic work): met in the model and tests. Sources, Dedup, Scoring, Tracker, ApplicationsManual and ProfileEdit are always available.
- AC2 (AI actions disabled with "Connect an agent" CTA): met at the component level (`Gated`, `notice.connect`). Adoption pending, see finding 2.
- AC3 (untrusted tasks disabled when the CLI lacks lockdown, reason "needs a fully locked-down CLI"): met. `CliUnsupported` maps to `unsupportedTitle`.
- AC4 (shared `useCapability` + `Gated`, no per-feature reimplementation): met.

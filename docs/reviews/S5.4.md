## Findings

### F1 — medium — persisted pause is never restored after a passphrase unlock (AC2)

- **Where:** `src-tauri/src/tray/run_controls.rs` (`restore_paused`, called only from `install`); `src-tauri/src/lifecycle/mod.rs:51` (install runs after `wiring::mount` in setup).
- **Trace:** `restore_paused` returns early when the store port is not mounted. In passphrase mode the store is locked at launch, so `install` sees no store, the tray flag stays `false`, and the stored `schedule.paused = true` is ignored. Unlock goes `mount_with_key` → `adopt` → `mount_ports` (`wiring/mod.rs:185-205`); nothing re-runs `restore_paused`.
- **Repro:** passphrase mode → Pause schedule → quit → relaunch → unlock. Expected: tray shows Paused and no scheduled run. Actual: tray shows Idle and the daily search runs at the next slot. The DB row still says `true`, so the state the user sees and the stored state disagree.
- **Fix:** make the restore retry until the store is open. For example, keep a `restored: bool` in `Painted` and call `restore_paused` from `paint_current`/`refresh` until it succeeds, so the first pulse or unlock applies the stored pause. Add a test: locked store at install, then mount, then `tray::schedule_paused` is `true`.

### F2 — low — cache written before the no-tray early return (comment is wrong)

- **Where:** `run_controls.rs`, `paint_current`.
- **Trace:** `*last = Some(status.as_str())` runs before the `app.tray_by_id(TRAY_ID)` early return. If no tray exists on one call, the cache says "painted". A later call with the same status returns at the cache check, so the icon never paints even after a tray appears. The doc comment says "nothing is lost if an icon appears later", which is not what happens.
- **Fix:** record `last` only after `set_icon` succeeds (or after the tray is found), or correct the comment. In production the tray is attached before `run_controls::install`, so this is latent, not user-visible today.

### F3 — note — login launch may flash the window (AC1)

- `tauri.conf.json` `main` window has no `"visible": false`, so it is shown by default and `start_hidden` hides it in `install`. A brief flash on login is possible. I did not verify it on a real login. Suggest a visual check on macOS, or `visible: false` with a show on manual launch. Non-blocking.

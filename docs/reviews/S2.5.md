## Findings

### F1 — Budget keeps the first N in fetch order, not the top-ranked offers (medium)

- `daily_search/mod.rs:420`: `new_ids.iter().take(pass.max_tasks)`.
- `new_ids` is filled in ingestion order (`daily_search/mod.rs:329`, `remember(new_ids, ...)`).
- Deterministic scoring runs after the agent pass (`daily_search/mod.rs:268` agent pass, `:270` score), so the run never selects by rank.
- `budget::plan()` (`boba-agent/src/budget/mod.rs`) is the only rank-aware split, and it has no caller outside tests.
- The tests `only_the_top_n_candidates_get_llm_features` and `the_budget_never_reorders_the_rank` pass against an unused function, so they give false assurance about the run.
- PRD §6.3 (`docs/product/PRD.md:192`) says offers over the budget are the ones ranked from deterministic factors; the module doc says "The input order is the rank order". The run does not do this.

**Expected:** the N offers handed to the agent are the top N by deterministic rank among those needing LLM features, and `run_agent_pass` consumes `plan().analyse`.
**Actual:** the first N new postings in fetch order; `plan()` is dead on the run path.
**Fix options:** (a) compute deterministic rank for the new ids before the agent pass and call `plan()` from `run_agent_pass`; or (b) if fetch order is the intended rule, delete `plan()` and its rank tests, and state the rule in the module doc and PRD note. Option (a) matches the spec.

### F2 — Every Offer without an agent pass is marked "not yet analysed", including with no engine (medium)

- `offers/mod.rs` `not_analysed`: marks every Offer whose agent pass has not run at the current Profile version (`version > 0`).
- It never checks whether an engine is configured. In Limited mode (no Agent CLI, EXPERIENCE §9.14) no pass can run, so every Offer shows the badge.
- The spec and PRD scope the marker to offers over the budget ("when more Offers need LLM features").

**Expected:** the marker appears only for offers that were deferred by the budget, or, if the badge is meant for all un-analysed offers, it is hidden when no engine is chosen.
**Actual:** Limited-mode users see "Low confidence: not yet analysed" on every Offer, which reads as a fault rather than a budget outcome.
**Fix:** scope the marker to deferred offers (record the deferred ids for the run), or skip the marker when no engine is configured, and add a test for each case.

## Findings

### F1 — Medium: the "click opens Today" is armed on show and never expires
- `src-tauri/src/notifications/mod.rs` — `arm_open_today` sets `OPEN_TODAY_PENDING = true`; `claim_pending_open` clears it on the next `Focused(true)`. Nothing bounds the wait.
- Repro: a digest is shown at 10:00 while Boba is in the background and the click never happens (dismissed, or the user just switches to the app). At 15:00 the user opens Boba from the dock or taskbar. The next focus claims the pending flag and emits `notification.opened`, so the app navigates to Today mid-task.
- Expected: only the notification click deep-links to Today (AC1). Actual: any later focus does.
- Fix: expire the pending open after a short window (for example 2 minutes from `arm`), and clear it when the digest port reports the show failed. Add a test with an injected clock or a timestamp check.

### F2 — Medium: the `needs_you` event toggle does nothing
- Stored in `NotifyEvents.needs_you` (`src-tauri/crates/boba-app/src/digest/settings.rs`) and rendered at `src/features/settings/notifications/index.tsx:133`. No `Notification` variant maps to `EventKind::NeedsYou` in `src-tauri/src/scheduler/notify.rs::allows`, and no code path reads it.
- Repro: switch "needs you" off in Settings, then trigger every notification path. Nothing changes.
- Expected: AC3 says the user can choose which events notify. A toggle that changes nothing breaks that promise.
- Fix: either remove the toggle and the field until a needs-you notification exists, or map the notification that belongs to it to `EventKind::NeedsYou` and test it. Name the choice in the review reply.

### F3 — Medium: quiet hours only silence the digest
- `digest::decide` checks `quiet_hours`. `TauriNotifier::notify` (`src-tauri/src/scheduler/notify.rs`) checks only `allows()` and never checks quiet hours. So `SourceFailing` and `OutboxHold` notices fire during quiet hours.
- AC2 says a run that ends during quiet hours shows nothing unless the user enabled a notification. Those notices come from the same run.
- Fix: apply the quiet-hours check in the shared notifier path for the non-security notices (the security notices stay exempt per the orchestrator's ruling). Or, if the scope is intentional, say so in the Settings copy and in this review's reply.

### Accepted / notes (no action)
- The locked-store and paused-board notices bypass prefs and quiet hours. This matches the orchestrator ruling of 2026-10-17 and is covered by `the_users_choices_gate_what_they_can_silence`.
- The click is inferred from window focus because the desktop notification plugin reports no click. This is disclosed in the commit body and matches the S5.3 design. F1 is the cost of that approximation.
- Settings clamps `top_matches_shown` to `MAX_TOP_MATCHES` and quiet hours to 0–23 on save (tested). Good.

## Outbound destination audit (orquestador check)

Every HTTP and socket path was traced to a `network_log::record` call:

- `boba-sources` `HttpClient::get` → `get_for(Sources)`; `get_for` and `post` record host and time. Covers all Source adapters, custom feeds and RSS test-fetch.
- FX (`get_for(Fx)`) is recorded and reached only when the user enables FX.
- Email: Gmail send, Gmail read, Graph send/read, OAuth authorise and token URLs (`record`), IMAP and SMTP (`record_host`).
- Browser driver, session and session-forms: `record(Sources, url)`.
- Agent CLI: `record_host(AgentCli, cli id)` at spawn.
- Frontend: no `fetch`, XHR, WebSocket or beacon calls outside the Tauri IPC.
- Payloads and secrets: the log keeps host only (`host_of`), and `clean_label` rejects paths, queries, whitespace and `@`. Notes carry only the feed name, model id and CLI id.

## Findings

### F1 (blocking) — model download is not recorded when it happens

- `src-tauri/crates/boba-embed/src/encoder.rs:172` — `download_model_files` calls `hf_hub` `repo.get(...)` for every model file against `huggingface.co` with no `network_log::record` call.
- The Settings row is only produced by `EmbeddingsService::network_activity` (`boba-app/src/embeddings/mod.rs:167`), which reads `DESTINATION_KEY` and `DOWNLOADED_AT_KEY`. Those are written after a successful download.
- Expected (AC1): every outbound destination is listed. Actual: a download in progress, or one that fails after reaching huggingface.co, is not listed at all.
- Fix: record the model host with `network_log::record(Purpose::ModelDownload, ...)` (or `record_host`) before the first `repo.get`, so each attempt is counted. `boba-embed` already depends on `boba-app`. Add a test that a failed download still leaves a `ModelDownload` row.

- `src-tauri/tauri.conf.json:44-48` sets `updater.active = true` with a `github.com` endpoint, and `src-tauri/src/lib.rs:78` registers the plugin. No frontend or Rust code calls `check()` yet, so no update request happens today.
- S10.5 must record `Purpose::Update` at the point where it performs the check, not only through the `network.update_checks` setting.

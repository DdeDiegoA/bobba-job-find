## Findings

**F1 (low): `appliedAt` compares timestamps as strings.** `src/features/tracker/nudges/due.ts` `appliedAt()` uses `event.created_at > latest`. The production clock formats with the `time` crate's RFC 3339, which trims trailing zeros. So `…:00Z` sorts after `…:00.5Z`, which is earlier. Effect: the wrong "entered Applied" time is picked only when two Applied events fall in the same wall-clock second. Practically unreachable through the UI. Suggested fix: compare `Date.parse(...)`. Not blocking.

**F2 (nit): misleading doc.** `boba-app/src/apply/guard.rs` `DuplicateGuardView.days_ago` says "Whole local days", but the value is computed from UTC RFC 3339 timestamps. Reword to "whole days". Not blocking.

**Quiet-hours parity.** The sweep returns early on `!allows(Digest)` and on `covers(hour) && !notify_during`. The notifier's `allows()` uses the same switch and `awake()`, which is `!covers(hour) || notify_during`. The sweep marks a nudge only after an attempt, and it never marks a held nudge, so a night-time sweep does not consume it.

**Residual R1 (low, accepted).** `let _ = notifier.notify(...)` discards the error, and the `nudge.sent` marker is written regardless. A transient OS notification failure therefore consumes that threshold's nudge permanently. The code comment states this is deliberate, to avoid a retry every minute. Acceptable for MVP. Revisit if users report missed nudges.

## Findings

### B1 — blocker: app panics at every start (duplicate `BrowserPort` mount)
- `src-tauri/src/wiring/port_list.rs:141-147`: a second `mount_port::<dyn BrowserPort>(app, Arc::new(ChromeDriver::new(data)))` right after the existing mount at `:133`. `mount_port` asserts on a duplicate registration (`src-tauri/src/wiring/mod.rs:224`).
- Expected: one `BrowserPort` mounted; app starts. Actual: `duplicate port line in port_list for dyn boba_app::ports::browser::BrowserPort`, panic in `mount_ports` on every launch. Same panic fails 4 wiring tests.
- Fix: delete lines 141-147 (the duplicate block). `SessionFormPort` mount at `:149-154` stays.

### H1 — high: session fill runs on any page the window shows, not only the board
- `src-tauri/crates/boba-app/src/apply/session/mod.rs` `fill()` (`snapshot` → `fill_page`) never checks `SessionBoard::allows(&page.url)`. `start()` checks only the offer URL before navigation (`:403`-ish, `board.allows(url)`), and `open()` clicks `OPEN_APPLY_JS` that can leave the board.
- Reachable: user clicks "Apply on company site" or any navigation in the headed window, then "Fill step". Boba types CV contact data and attaches verified PDFs into a third-party page inside the signed-in session. This breaks the rule on `SessionBoard::allows` ("Boba never drives it to a host the board did not name").
- Expected: `fill()` (and `start()` after `open`) hands back / refuses when the live page host is not the board. Actual: fills.
- Fix: check `board.allows(&page.url)` before `fill_page`; return a handoff (new kind or `OffBoard`) and fill nothing. Add a test: off-board page → zero `fill_text`/`attach` calls.

### M1 — medium: kill switch fails open on a lookup error
- `src-tauri/src/commands/apply.rs` `session_service`: `.with_kill_switch(wiring::port::<dyn KillSwitchPort>(app).ok())`. A missing or failed port becomes `None`, which the core reads as "not engaged". The ATS and manual paths in the same file use `?` (`:223`, `:411`).
- Fix: `Some(wiring::port::<dyn KillSwitchPort>(app)?)`, consistent with the other paths.

### M2 — medium: audit intent written after the form is typed
- `start()`: `browser.open` + `fill_page` run before `audit_append_intent(...)?`. If the audit write fails, the window stays open with fields typed and no intent row. AD-12 wants the attempt on record before the browser acts.
- Fix: write the intent before `fill_page`; on failure, `browser.close()` and return the error.

### M3 — medium: review-mode challenges do not pause the Source
- Captcha / unusual activity / rate limit hand back in review mode, but nothing writes `session.pause.<source>`. `gate()` reads that key, but only the S11.1b search run writes it (`boba-sources`). A challenge seen in the apply window does not block the next start or fill.
- Fix (recommended, matches AD-10 "a challenge pauses the Source"): write the same pause key on a challenge in `fill`/`start`, or record in the ADR why review mode is exempt.

### M4 — medium, needs ruling: no `decide()`, spacing or daily cap on session starts
- Orquestador's brief asked for `decide()` + spacing + kill switch + Ready gate on every submit. The session path has the kill switch, opt-in, pause, board host and Ready gate at `start()`, but **no** `decide()`, no `spacing_sample`/pacing gap, and no S9.6 daily cap. Boba never presses submit (the user does), so this is a policy call, not a code bug.
- AGENTS.md locks "session-board auto-apply: per-source opt-in, ToS/ban warning, **caps**, kill switch, audit log". Review mode is not auto-apply, but each start drives a signed-in LinkedIn/Indeed session.
- Recommended: count `apply_session_start` against the daily cap and the 30s session pacing floor, or record why review mode is exempt. **Residual for Diego/orquestador.**
- Related: `fill()` does not re-run the Ready/verified gate, so the package can change between start and fill. Recommended: re-run the view gate in `fill()`.

### L1 — low: a premature Confirm forfeits the attempt
- `confirm()` on a page without confirmation writes `Failed` to the intent, closes the browser and returns `NeedsCheck`. The attempt is resolved, so a later confirm after the real submit is `UnknownAttempt`; the user must restart (a second intent row). Consider a non-terminal `NeedsCheck` that keeps the window open.

### L2 — low: plaintext PDF can outlive a crash
- `session_forms/driver.rs` `attach()` writes the verified PDF to `app_data/uploads/session/` and removes it after the call. The remove runs on error paths, but a crash between write and remove leaves a plaintext copy (AD-13: must not outlive the upload). Recommended: sweep `uploads/session/` at startup.

## What holds (checked in code and tests)

- Launch: headed (`with_head`), per-Source profile (`launch_plan` re-validates the id), ephemeral loopback CDP port (`cdp_port: 0`).
- Cookies: never read. `OPEN_APPLY_JS` / `READ_APPLY_JS` are tested to contain no `submit`, `requestSubmit`, `FormData`, `document.cookie`, `fetch(`, `XMLHttpRequest`, `localStorage`.
- Fill injection: `forms::fill_script` embeds `handle`/`value` as serde JSON; value cannot become JS source.
- Passwords excluded from the fillable set; unapproved answers never typed (tested).
- Gate on `start`: https + board host (`SessionBoard::allows`, lookalike hosts refused), opt-in, source enabled, pause, kill switch, Ready/verified via `manual().view`.
- Opt-in revocation stops `confirm` (tested). Confirmation only counts on the form's host (`same_host`, tested).
- Audit: `apply.session_submitted`, URL without query, no page text, attempt bound to the application (`intent()` checks `target_id`).
- No auto-submit: the UI starts / fills / confirms only on click; `useEffect` absent in `session-assist.tsx`.

## Acceptance criteria

- **AC1 (send from my account, audit intent/outcome, Applied):** covered. The review screen shows recipient, subject, body and attachments. Send writes the intent, sends, writes the outcome naming the message id, then moves the card to Applied. Test `sending_writes_intent_then_sends_then_writes_outcome_and_moves_the_card`.
- **AC2 (never sent twice on retry):** covered. Prior attempts are read before insert (`check_evidence`). `sent` refuses, `pending` asks for a check, `uncertain` needs `confirm_resend`, `failed` may retry. A partial unique index blocks a second live attempt per application. Startup recovery reconciles interrupted sends (`recover`): it closes each open apply intent with `unknown_after_crash` before flipping `pending` rows to `uncertain`. Tests cover crash-between, idempotent second startup, and other areas' intents left alone.
- **AC3 (unverified documents never attached, AD-14):** covered. Attachments come only from verified exports (`export_pdfs`). Test `an_unverified_draft_is_named_and_not_attached`.

The audit is conservative and the send is still blocked by `check_evidence`. Accepted; revisit only if the audit UI needs the distinction.
- Message id is Boba-assigned (`<attempt-id>@boba.local`) because Graph `sendMail` returns no id. The attempt id is the audit correlation.

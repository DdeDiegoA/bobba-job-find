## Non-blocking notes

1. **P3 — ownership `files`.** New `boba-domain/src/source/**` plus the one-line `pub mod` in `boba-domain/src/lib.rs`, the `src-tauri/Cargo.toml` reqwest feature fix, and `boba-sources/Cargo.toml` deps are outside S4.1's listed `files`. dev's call was right: per the AD-14 ruling, port types live in `boba-domain`. **Fix:** pm adds `boba-domain/src/source/**`, `boba-domain/src/lib.rs`, the two manifests and `Cargo.lock` to S4.1 `files`.
2. **P3 — rate-limiter key includes the interval** (`origin|interval_ms`). Two sources on the same host with different `min_interval_ms` get **separate** buckets, so the coarser one can exceed the stricter host rate — AD-10 says one bucket per host. Recommend keying on `origin` and storing the strictest interval seen, or document the current choice.
3. **P3 — redirects.** `reqwest` follows redirects by default; the robots check and the token bucket are keyed on the *request* URL's origin, so a redirect to another origin bypasses both for the final URL. `reqwest::redirect::Policy::none()` (or re-checking on the final origin) would close this. Not in the ACs; hardening.
4. **Note — `SourcesRepo` is not `Send + Sync`** because `boba_store::db::Store` is `!Sync` (the writer actor holds an `mpsc::Sender`). Documented in the trait; it will constrain wiring repos into Tauri state / async use cases later. Flag to the architect — likely needs the writer handle to be `Sync` (e.g. a channel with a `Sync` sender) before the command surface lands.

## Bugs (round 1, all closed)

### B1 (Medium, closed in round 2) — A11Y-7: the Auto confirmation is not a trapped modal

`settings/applying/rules/index.tsx` binds the Tab trap and Esc to `onKeyDown` on the
dialog `<div>`. Keyboard events that start on `document.body` never reach that node, and
nothing else pulls focus back in. The panel keeps `aria-modal="true"`, but the background
is not inert.

Repro (throwaway jsdom test, deleted afterwards): open Enable Auto, blur, move focus to
`document.body`, press Tab.
- Expected: focus stays inside the dialog (A11Y-7: "Tab is trapped").
- Actual: `focusInsideDialog: false`, `active: BODY`, `inertNodes: 0`.

In a browser the same sequence sends the next Tab to the first focusable control in the
page (sidebar, topbar), outside the dialog. The fix in the finding only holds for keyboard
users who never leave the dialog.

Required fix (either):
1. While `confirming`, listen on `document` for `focusin`; if the target is outside the
   dialog, move focus to `acceptRef`. Keep `aria-modal`. Add a test: `focusin` on an
   outside control, focus returns to the checkbox.
2. Or make the rest of the page `inert` while the dialog is open. The dialog is inline in
   `<main>`, so this needs a sibling-walk; option 1 is smaller.
If neither is done, drop `aria-modal` and keep it a labelled region (the finding allows
that), and update the test title.

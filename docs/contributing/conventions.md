# Conventions

The rules below are enforced by tooling wherever possible. If a rule is only
prose, it is because no cheap check exists yet — prefer adding the check.

New to the codebase? Read [ai-agents.md](ai-agents.md) first for the
architecture map and the security invariants.

## Formatting

| Area | Tool | Command |
|---|---|---|
| TypeScript, TSX, JSON, CSS, Markdown-adjacent config | **Biome** | `pnpm lint` (check), `pnpm format` (write) |
| Rust | **rustfmt** (`rustfmt.toml`) | `cargo fmt --all -- --check`, `cargo fmt --all` to write |
| Editors | **EditorConfig** (`.editorconfig`) | applied by the editor |

- ESLint and Prettier are **not** used. Biome replaces both; do not add a
  second JS/TS linter or formatter.
- Line endings are LF (`.gitattributes` `* text=auto eol=lf`), UTF-8, final
  newline, no trailing whitespace except in Markdown.
- Indentation: 2 spaces for JS/TS/JSON/CSS/YAML, 4 for Rust, SQL and Python.

## Rust lints

The workspace opts every member into `[workspace.lints]` (`[lints] workspace =
true` in each manifest). CI runs
`cargo clippy --workspace --all-targets --locked -- -D warnings`, so any lint
that fires is a build failure.

Current lints: `unsafe_op_in_unsafe_fn`, `dbg_macro`, `todo`,
`undocumented_unsafe_blocks`. Every `unsafe` block carries a `// SAFETY:` line
explaining why it is sound. `unimplemented!` is allowed on purpose: mail test
doubles stub the calls the send/read path never makes.

Adding a lint is welcome when the tree already satisfies it; a lint that fights
existing code is noise, not a gate.

## Naming and structure

- Tauri event names: `<area>:<verb-ed>`, for example `task:progressed`,
  `kill_switch:changed`. **Never a dot** — Tauri 2.12 rejects dotted event
  names at runtime (CH10). Present tense or noun-first names are also out.
- Commands: `<area>_<verb>` (`profile_save_fact`, `backup_restore`).
- i18n keys are flat dotted strings: `area.section.key`, and core errors are
  `errors.<area>.<key>`.
- Migration files: `NNNN_snake_case_name.sql`, contiguous from `0001`.
- Files: `snake_case.rs`, `kebab-case.ts(x)` where it is a component file,
  `camelCase.ts` for modules.

## Generated files

- `src/lib/ipc/bindings.ts` is generated by `scripts/gen-bindings.mjs`. Never
  hand-edit it; CI fails when it is stale.
- Never hand-merge `Cargo.lock`, `pnpm-lock.yaml` or any lockfile. Rebase and
  regenerate (`cargo build`, `pnpm install --frozen-lockfile` when unchanged).
- `.hermad/`, `.claude/`, `.opencode/`, `.agents/` are local agent-tooling
  state and are gitignored. Do not commit them.

## The conventions checker

`scripts/ci/check-conventions.mjs` runs in CI's `hygiene` job and in the
pre-commit hook. It is a static check — no build, under a second.

| Rule | What it checks |
|---|---|
| Event names | No `.` in any `event_name = "..."` attribute or `emit("...")` literal |
| Error catalogs | No `errors.*` key in `common.json`; every `locales/*/errors/<area>.json` is listed in `ERROR_FRAGMENTS`; EN and ES carry identical keys |
| Migrations | Numbers unique and contiguous from `0001` |
| IPC list | `collect_commands!`/`collect_events!` appear only in `ipc/command_list.rs`; every `#[tauri::command]` fn is registered there |
| Port list | `mount_port::<...>` is used only in `wiring/port_list.rs`, or in a module whose `mount()` helper `port_list.rs` calls (ADR-012) |
| Adapter rule | `src-tauri/tests/dependency_rules.rs` is present (the real check is that cargo test) |

Run it alone with `pnpm check:conventions`. `pnpm check` chains it with Biome,
tsc and rustfmt.

## Pre-commit hook (optional)

Enable once per clone:

```sh
git config core.hooksPath .githooks
```

The hook runs the conventions checker, `cargo fmt --all -- --check`, and Biome
when `node_modules` exists. Skip a commit with `git commit --no-verify`; the CI
gate still runs everything.

## Commits and branches

- Branch per change: `hermad/<story>` in this project's workflow, or
  `<type>/<short-topic>` for outside contributions.
- Commit subjects use `type(scope): imperative summary`
  (`fix(session): notify when a challenge pauses Auto on the apply path`).
  Types in use: `feat`, `fix`, `docs`, `test`, `chore`, `refactor`, `perf`.
- One logical change per commit; keep generated files out of conflict-prone
  merges rather than resolving them by hand.
- Explain *why* in the body when the diff does not say it. Reference story or
  ADR ids when one applies.

## Documentation

- All documents and code comments are in **English**.
- The spine (`docs/architecture/ARCHITECTURE-SPINE.md`) is the source of truth;
  a design change updates the spine or adds an ADR before the code lands.

## Architecture map

Hexagonal modular monolith: one Rust core process, one React UI, no second
runtime (AD-1). The UI is a client of typed IPC; it holds no business logic.

```
src/                     React UI (TypeScript). No invoke(), no business rules.
  lib/ipc/bindings.ts    GENERATED by scripts/gen-bindings.mjs — never edit.
src-tauri/               Tauri shell (commands, events, tray, lifecycle, wiring).
src-tauri/crates/
  boba-domain/           Pure types + rules. Depends only on serde, thiserror, time, ulid.
  boba-app/              Use cases, ports (traits), i18n catalogs, error keys.
  boba-store/            SQLCipher storage, repos, migrations, backup, keys.
  boba-sources/          Source adapters (RSS, ATS JSON, aggregators, session boards).
  boba-agent/            Agent CLI drivers, lockdown, budgets, MCP server side.
  boba-mcp-proto/        Wire contract for the boba-mcp shim.
  boba-mcp/              The only first-party sidecar (stdio shim).
  boba-mail/             Gmail / MS Graph / IMAP / SMTP.
  boba-docs/             Typst PDF + DOCX rendering.
  boba-browser/          chromiumoxide driver for opt-in session boards.
  boba-embed/            Optional local embeddings.
locales/{en,es}/         UI + core catalogs; errors/<area>.json per area (CH7).
scripts/ci/              Static gates run by CI's `hygiene` job.
```

Dependency rules are executable, not advisory:
`src-tauri/tests/dependency_rules.rs` (runs under `cargo test`).

- `boba-domain` depends on nothing but `serde`, `thiserror`, `time`, `ulid`.
- Adapters never depend on other adapters.
- `boba-app` depends on ports, never on an adapter and never on Tauri.
- Only `boba-store` opens the database (AD-2). Agents and the UI go through
  core use cases.

Every type that crosses a port lives in `boba-domain`.

## The seams (ADR-012) — extend these, never the root

The composition root is append-only. A slice adds one line and stops:

| Seam | File | Rule |
|---|---|---|
| Commands and events | `src-tauri/src/ipc/command_list.rs` | Append one fully-qualified path per line, ending in a comma. `.gitattributes` marks it `merge=union`. |
| Ports | `src-tauri/src/wiring/port_list.rs` | Append one `mount_port::<dyn Port>(app, ...)` line, or one `module::mount(app)` helper call. |
| Use-case modules | `src-tauri/src/commands/<area>.rs` | One file per area; add its `pub mod` line in `commands/mod.rs`, then register each command in `command_list.rs`. |
| Lifecycle hooks | `src-tauri/src/lifecycle/mod.rs` | Window/tray/single-instance have no union seam; extend `install`. |
| Event bus | `src-tauri/src/events/mod.rs` | Typed events, registered in `command_list.rs`. |

Never edit `src-tauri/src/lib.rs` to register something; it only calls
`wiring::mount(app.handle())` and `ipc.mount_events`. Never edit
`src-tauri/src/ipc/mod.rs`: it is the single `tauri_specta::Builder` site.

## IPC and events

- Every command is `#[tauri::command]` + `#[specta::specta]` and returns
  `Result<T, AppError>`.
- Events are typed structs carrying `#[tauri_specta(event_name = "<area>:<verb-ed>")]`.
  **No dots in event names** — Tauri 2.12 rejects them at runtime (CH10). The
  rule is enforced by `ipc::tests::every_registered_event_name_is_legal_for_tauri`
  and by `scripts/ci/check-conventions.mjs`.
- After adding a command or event, regenerate bindings:
  `node scripts/gen-bindings.mjs` (or `--check` to verify freshness). The file
  `src/lib/ipc/bindings.ts` is generated; hand edits fail CI.
- The UI uses commands to write and events to invalidate TanStack Query caches.
  No direct `invoke()`, no server state mirrored in Zustand.

## i18n

- UI and core read the same catalogs: `locales/{en,es}/*.json` (flat dotted
  keys, e.g. `errors.unknown`).
- Core error keys live **one file per area**: `locales/{en,es}/errors/<area>.json`.
  Never put `errors.*` into `common.json`.
- A new area is: the two JSON files, identical key sets in EN and ES, and one
  line in `error_fragments![...]` inside
  `src-tauri/crates/boba-app/src/i18n/mod.rs`.
- `scripts/ci/check-conventions.mjs` enforces all of the above; a Rust test in
  `boba-app/src/i18n/mod.rs` checks the same at runtime.

## Migrations

- Location: `src-tauri/crates/boba-store/migrations/NNNN_name.sql`.
- Numbers are unique and contiguous from `0001` with no gaps. A slice takes the
  next free number **at rebase time**, not the number its story text mentions.
- Migrations are append-only. Never edit a shipped migration; write a new one.
- `scripts/ci/check-conventions.mjs` checks uniqueness and contiguity;
  `src-tauri/crates/boba-store/tests/db.rs` covers migration discovery and the
  writer/read-pool split on temp databases.

## Tests and environment hygiene

- Tests never touch real user data. No real Keychain, no real
  `~/Library/Application Support`, no real network.
- Do not call `wiring::store_config` / `wiring::mount` / `mount_with_key` under
  `tauri::test::mock_app()`: `app_data_dir` resolves to the **real** user
  directory. Use `tempfile` temp dirs and injected fakes.
- Keychain tests use the mocked store only.
- Agent CLI tests use `tools/fake-cli`; HTTP tests use recorded fixtures.
- Timers and clocks are injected ports; tests never sleep their way to a
  result.

### Fresh worktree / fresh clone

Run `pnpm install` **before** `node scripts/gen-bindings.mjs`. Without a
formatted toolchain (Biome via pnpm), the generator can write an empty
`src/lib/ipc/bindings.ts` and CI then reports a stale-bindings failure.

## The CI gate

Run the same commands locally before handing a branch over. CI mirrors them.

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm lint                        # Biome (lint + format check)
pnpm typecheck                   # tsc --noEmit
pnpm test                        # Vitest
node scripts/ci/check-i18n.mjs
node scripts/ci/check-conventions.mjs
node scripts/gen-bindings.mjs    # then `git diff --exit-code -- src/lib/ipc/bindings.ts`

CARGO_INCREMENTAL=0 cargo fmt --all --check
CARGO_INCREMENTAL=0 cargo clippy --workspace --all-targets --locked -- -D warnings
CARGO_INCREMENTAL=0 cargo test --workspace --locked
cargo deny check
```

`CARGO_INCREMENTAL=0` keeps CI artifacts deterministic and avoids stale
incremental state in shared target directories. `scripts/ci/check-workflow-policy.mjs`
and `python3 scripts/gen_stories.py --check` also run in the `hygiene` job.

## Security invariants — never weaken

These are product requirements, not style. A change that relaxes one is a
security gate: stop and escalate; do not self-approve.

1. **Tool lockdown gate (AD-6, ADR-010).** A task with untrusted input runs
   only on a CLI whose per-run `init` event lists exclusively `mcp__boba__*`
   tools. Missing/unverifiable `init` ⇒ fail closed. No user override exists.
2. **LLM proposes, core disposes (AD-5).** The agent never writes a score,
   a status, a submission or an email. No MCP tool submits, sends, deletes or
   changes settings.
3. **Untrusted content (AD-7).** Postings and email bodies are untrusted: MCP
   envelope, sanitized HTML (ammonia), plain text only, no automatic fetch of
   links inside third-party text. Agent output from a tainted run inherits the
   taint.
4. **Server-side apply gate.** Every apply path re-checks Ready + verified in
   the core; the UI check is not the gate.
5. **Kill switch and caps.** Every auto-send path consults the kill switch,
   the daily caps, pacing floors and the challenge pause. Never bypass a cap
   for a retry.
6. **Network policy (AD-10).** All HTTP through the core `HttpClient`: honest
   User-Agent, robots.txt, per-host limits, no CAPTCHA solving or fingerprint
   spoofing, https-only apply URLs.
7. **Secrets.** Keychain via `keyring-core`; no secrets in logs, error
   messages, exports, audit entries, or crash reports. No secret ever reaches
   the webview or an agent.
8. **Audit chain (ADR-011).** Canonical form and hash chaining are fixed; a
   retention sweep must not touch it.
9. **Local-only.** No cloud, no telemetry, no accounts. The only outbound
   traffic is the sources, email and update endpoints the user configured.

## Adding things: short checklists

**A command:** implement in `src-tauri/src/commands/<area>.rs`, one line in
`ipc/command_list.rs`, `node scripts/gen-bindings.mjs`, i18n keys if it emits
errors, tests.

**An event:** typed struct in the owning module with
`event_name = "<area>:<verb-ed>"`, one line in `ipc/command_list.rs`'s
`boba_events!`, regenerate bindings.

**A port:** trait in `boba-app/src/ports/`, implementation in exactly one
adapter crate, one `mount_port` line in `wiring/port_list.rs`, types it crosses
in `boba-domain`.

**A migration:** next free `NNNN_name.sql`, repo methods in `boba-store`, a
test against a temp database (never a real one).

**An error area:** see [i18n](#i18n).

## Commits

Small, one slice per branch, imperative subject, no generated files forced into
a conflict. Lockfiles are never hand-merged: rebase and regenerate. See
[conventions.md](conventions.md) for the hook and the checker.
